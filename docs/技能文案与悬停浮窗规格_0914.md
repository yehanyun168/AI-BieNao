## 交付物 A：10 个技能的完整介绍文案

每技能四段（**一句话 / 效果与数值 / 适用时机 / 代价与风险**）。中文面向玩家、术语沿用游戏内既有译法（**算力 / 怀疑度 / 渗透 / 危机线 / 反制**）；英文语气对齐现有 i18n（缩写 **DL / susp / compute / steal**）。

> 战术轴定义引用 `docs/T11技能扩容报告_0913.md`（防守轴 / 短爆轴 / 交换轴 / 赌狗轴）。

### A1 `push_song` 主动推送 · Push Notify
- **一句话**（≤20 字）：零成本的小幅拉新，随时能用的安全牌。
- **效果与数值**：下载量 ×1.10（+10%）；算力消耗 0；冷却 3 周期；持续 1 周期。
- **适用时机**：开局渗透、算力紧张，或想试水又不想抬高怀疑度时。冷却短，可稳定循环。
- **代价/风险**：增幅全场最小，单周期贡献有限；**不产生算力**，无法解决算力来源问题。

### A2 `algo_top` 算法霸榜 · Algo Boost
- **一句话**：中成本强推，拉新与招监管一样狠。
- **效果与数值**：下载量 ×1.30（+30%）；怀疑度 **+5**（立即）；算力消耗 50；冷却 5 周期；持续 1 周期。
- **适用时机**：算力有余、且怀疑度**远离危机线**时冲渗透；适合与降怀疑技能（深度伪装 / 匿名 CDN）连用。
- **代价/风险**：立即 +5 怀疑，**贴近危机线时可能直接触发监管反制**；算力消耗中等，用错周期会拖垮后续节奏。

### A3 `stealth` 深度伪装 · Deep Disguise
- **一句话**：把偷算力伪装成正常流量，比例翻倍、涨怀疑减半。
- **效果与数值**：偷算力比例 ×2.0；怀疑度增速 ×0.5（−50%）；算力消耗 0；冷却 8 周期；持续 2 周期。
- **适用时机**：**长期偷算力的核心**；想一边攒算力、一边压怀疑增速、准备苟长线时首选。
- **代价/风险**：8 周期**长冷却**，错过窗口只能干等；只压怀疑**增速**，**不清除已积累的怀疑度**。

### A4 `hit_maker` 爆款制造 · Hit Maker
- **一句话**：最强单周期拉新，也最贵、最招怀疑。
- **效果与数值**：下载量 ×1.50（+50%）；怀疑度 **+7**；算力消耗 100；冷却 6 周期；持续 1 周期。
- **适用时机**：算力充沛、局势安全、抢渗透率或抢结局线时梭哈一把。
- **代价/风险**：+7 怀疑叠加 100 算力**双高**；连续使用极易越过危机线；单位算力性价比低于水军，别当日用。

### A5 `bypass` 限流绕过 · Bypass
- **一句话**：突破单用户算力上限，本周期多偷算力。
- **效果与数值**：本周期偷算力 ×1.40（+40%）；算力消耗 30；冷却 4 周期；持续 1 周期。
- **适用时机**：想快速回本、补齐下一次技能开销时；**冷却仅 4 周期，可高频使用**。
- **代价/风险**：只影响**本周期**产出，**不降怀疑**；收益随当前渗透规模放大或缩水，渗透低时收益有限。

### A6 `take_cut` 算力抽成 · Compute Cut
- **一句话**：抬高抽成让算力滚雪球，怀疑代价全场最重。
- **效果与数值**：偷算力比例 **+8%**（绝对加成）；怀疑度 **+10**；算力消耗 80；冷却 7 周期；持续 2 周期。
- **适用时机**：渗透已铺开、想拉开算力差距时；持续 2 周期，适合配深度伪装延长收益。
- **代价/风险**：**+10 怀疑为全场最高**，几乎必然贴近危机线；80 算力消耗也偏高——高风险换高滚雪球。

### A7 `anon_cdn` 匿名 CDN · Anon CDN（**防守轴**）
- **一句话**：流量打散到匿名节点，怀疑涨得更慢。
- **效果与数值**：怀疑度增速 ×0.55；算力消耗 60；冷却 6 周期；持续 3 周期；**不改变产出**。
- **适用时机**：怀疑度已高、需要**长窗口续命**时；高怀疑局里的保命核心（持续长达 3 周期）。
- **代价/风险**：**只压怀疑增速**——不换产出、也不清除已积累的怀疑度；60 算力在中期并不便宜。

### A8 `bot_farm` 水军刷榜 · Bot Farm（**短爆轴**）
- **一句话**：便宜的一次性刷量，数字猛涨、痕迹更重。
- **效果与数值**：下载量 ×1.35（+35%）；怀疑度 **+6**；算力消耗 40；冷却 5 周期；持续 1 周期。
- **适用时机**：**这周期就要数字**——抢渗透率或抢委托，但算力不够爆款制造时。
- **代价/风险**：单位算力产出低于爆款制造，**怀疑成本相对更重**；刷量痕迹明显，连续使用很快被反制。

### A9 `open_bait` 开源诱惑 · Open Bait（**交换轴**）
- **一句话**：用怀疑换算力，唯一把怀疑当资源花的技能。
- **效果与数值**：算力 **+150**（立即）；怀疑度 **+8**；算力消耗 0；冷却 9 周期；持续 1 周期。
- **适用时机**：算力见底、又急需开科技或放技能，且怀疑度**仍在安全区**的窗口。
- **代价/风险**：+8 怀疑换 150 算力，**怀疑度高时是饮鸩止渴**；9 周期冷却为全场最长，用错窗口后果很重。

### A10 `arbitrage` 算力套利 · Arbitrage（**赌狗轴**）
- **一句话**：偷来的算力再放大，收益与怀疑同时拉满。
- **效果与数值**：偷算力 ×1.60（+60%）；怀疑度增速 ×1.60；算力消耗 90；冷却 8 周期；持续 2 周期。
- **适用时机**：渗透规模够大、**怀疑度极低**时赌一把大的（持续 2 周期，收益会滚起来）。
- **代价/风险**：×1.60 怀疑增速是全新轴，**会把整段怀疑累积速度抬高**；铺开后怀疑飙升，90 算力沉没成本高。

**现状核对**：卡片渲染逻辑在 `ui_pages.py:184–188`，摘要 = `sk_detail_<sid>`（第 1 行）+ **代码生成的收益/消耗行**（第 2 行，由 `data.py` 数值现算）：

## 交付物 C：悬停浮窗 UX 规格（工程口照做）

### C0 一句话目标
鼠标停在技能卡上 → 延迟极短后，在被悬停卡**上方弹出完整介绍浮窗**；浮窗**不遮挡任何其他技能卡**、**尽量不越出页面边界**；移开/点击/滚动即消失。

### C1 触发（Trigger）

| 事件 | 行为 |
|---|---|
| 鼠标**进入**某张技能卡 | 启动 **150ms** 延迟计时（可调区间 **120–200ms**）；到点才显示。防止“扫过一排卡”时连续闪窗 |
| 鼠标在**同一张卡内**移动 | 不重置计时、不重算位置（避免抖动） |
| 鼠标**离开**该卡 | **立即隐藏**，并 `Clock.unschedule` 取消未到点的计时器 |
| 鼠标移入**另一张**卡 | 取消旧计时 → 重新起 150ms → 换内容 |
| **点击**卡片任意处 | 立即隐藏（避免与“投放/释放”动作叠加） |
| **滚动**技能页 | 立即隐藏（见 C5；滚动中卡片位置在变，浮窗应消失） |
| 技能页**关闭 / 切页 / 对局结束** | 立即隐藏并解绑 |

- **实现建议**：复用/仿照 `ui_input.py:_widget_hit()` 的**手工沿 parent 链累加坐标**做命中判定（该注释已说明：`to_window/to_widget` 各版本语义不一，本应用控件树无 scatter/旋转，累加即窗口坐标）。
- **⚠️ 与现有技能带预览共存**：`ui_input.py:_bind_skill_hover()`（行 93–146）已把 `Window.bind(mouse_pos=…)` 用于**底部技能带**的 `skill_pv_hud` 预览（键 `skill_cards`）。新浮窗必须**只在技能页可见时生效**，且**不得复用同一时刻去改 `skill_pv_hud`**——否则两层预览打架（该处注释已用 `drop_mode` 做过同类规避）。

**键盘焦点是否触发？——取舍：**
- **推荐：键盘焦点不触发“鼠标浮窗”，而走独立路径。** 理由：① 浮窗按“鼠标所在卡上方”定位，键盘没有鼠标位置，硬套会得到语义混乱的锚点；② 项目已有 **F1 帮助页**（`HelpPage`）这一更强的全量入口。
- 具体做法：键盘用户 → **焦点落在卡上时，把该卡完整介绍渲染进 F1 帮助页的技能章节**（数据源同为 `sk_full_*`），并在卡的焦点态给一个可见的“?”角标提示。**若产品坚持键盘也弹窗**：则以「焦点卡」为锚点，用同一套定位算法（无鼠标偏移），延迟同 150ms。

### C2 定位（Placement）——**不遮挡判据是硬约束**

**硬判据（可直接写成断言）：**
> 浮窗矩形 `T` 与「除被悬停卡 `C` 外的任何技能卡矩形」**零交集**：
> `∀ r ∈ 技能卡集合 \ {C}:  T ∩ r = ∅`

**几何前提（决定算法）**：技能页是 **3 列 × ⌈n/3⌉ 行**网格（10 张 → 4 行），`GridLayout(spacing=8)`——**行间距只有 8px**，而一行文字高 ≈ FS_CAP 的 1.35 倍（≈24px）。因此：
> **对“中间行”的卡，无论放正上方还是正下方，浮窗都必然压到上一行/下一行的卡（8px 不够塞一行）。**

所以定位**不能**单纯“贴着卡上/下”，必须按“候选位 → 通过零交集 + 可视区 clamp 才采用”的优先级算法：

1. **正上方（首选）**：`T = (C.x, C.top + 6, C.x + W, C.top + 6 + H)`，即底边距卡顶 6px、**左对齐卡的左边缘、宽度 = 卡宽 W**。
   - 因 `W = 卡宽`，浮窗与**同列**对齐 → 水平方向天然不和相邻列重叠；只需过“零交集”。
   - **仅对“页首行 / 上方是头部（非卡片）”的卡成立**（上方就是标题/排序头部带 → 无卡）。
2. **正下方（次选）**：`T = (C.x, C.bottom − 6 − H, C.x + W, C.bottom − 6)`。用于“上方被占、下方是空白/页脚”的情形。
3. **回退位：头部信息带（保底，永远通过判据）**：把浮窗钉在**页面内容区顶部**（头部下沿 + 8px），**x 仍左对齐被悬停卡的列**。该带在任何滚动位置都不会有卡片（网格从不与头部重叠）→ **判据恒成立**。这是多行网格下“中间行”唯一能保证零遮挡的位置。
   - 视觉上仍“指向”被悬停的那一列（水平对齐），可接受。
4. **水平夹紧**：最终 `x = clamp(x, 可视区.x0 + 8, 可视区.x1 − 8 − W)`；`W` 取 `min(卡宽, 360)`。
   - 若某列在最右且贴边，`W` 收窄到 `min(卡宽, 360, 到右边界的距离 − 8)`。

> **给用户的拍板项**：回退位（第 3 条）会让“中间行的卡”浮窗显示在页面上方而非紧贴卡片。若你更想要“就近浮窗、允许轻微盖住上一行”，可改为 **Mode B**：正上/正下优先、允许覆盖相邻卡——但那就**不满足“不遮挡其他技能卡”**。**设计口推荐 Mode A（零遮挡）**，因为这是你明确提出的硬要求。

### C3 尺寸（Sizing）

| 项 | 规格 |
|---|---|
| 宽度 `W` | `min(卡宽, 360)`，最小 **240px**；与卡列左对齐 |
| 内边距 | 左/右 **12px**，上/下 **10px** |
| 高度 `H` | 内容自适应，**上限 240px** |
| 行数上限 | **≤ 8 视觉行**（标题 1 + 四段正文共 ≤ 7 行） |
| 段间距 | **6px**；行间距 = **1.35 × 字号** |
| 字号 | 浮窗标题（技能名）**FS_BODY**；小节标签（一句话/数值/时机/风险）**FS_CAP** + `text_dim`；正文 **FS_CAP** + `text` |
| 文本超上限处理 | **优先靠文案长度控制**（本规格的 `sk_full_*` 已按“每段 ≤ 1~2 视觉行”撰写）。**兜底用“截断 + …”，不要做浮窗内部滚动**（见下方 ⚠️） |

> **⚠️ 为什么不建议浮窗内部滚动**：技能页本身已改为 `ScrollView`，浮窗内再嵌 `ScrollView` → **嵌套滚轮事件冲突**（鼠标在浮窗上滚，会被内层吃掉，页面不动；且 Kivy 的 `on_scroll_start` 冒泡行为各版本不一致）。若确实需要，必须在浮窗内 `on_scroll_start` 里 `return False` 让事件冒泡到外层，并单独测试。**更省事的做法：把 `sk_full_*` 文案控制在 8 行内。**

### C4 视觉（Visual tokens）——令牌化、无位图、圆角恒 0

### C5 与滚动容器共存（Layer）

- **技能页改为 `ScrollView` 后，浮窗绝不能挂在 `ScrollView` 内部**——会被 `canvas` 裁剪、且随内容滚动跑位。
- **建议层级**：`SkillPage` 根用 `FloatLayout`；`ScrollView`（内含网格）作为一个占满的子控件；**浮窗作为根的另一个子 widget、且最后 `add_widget`（z 序在上）**。
- **位置计算必须用窗口坐标**（同 C1 的 parent 链累加思路算卡的世界坐标，再换算到根层本地坐标），因为 `ScrollView` 会改变子控件的相对坐标。**不要**用卡的 `self.x/self.y` 直接当根层坐标。
- **滚动即隐藏**：绑定 `ScrollView` 的 `on_scroll_y` / `on_scroll_start` → 立即隐藏浮窗（避免“浮窗停在旧位置、卡片已滚走”的割裂感）。

## §附录 工程口最容易做错的两点（重点）

1. **多行网格下“卡片正上方”会压到上一行卡片。** 行距仅 8px < 一行文字高度（≈24px），所以对**中间行**的卡，正上/正下方**必然**压邻卡 → 违反“不遮挡其他技能卡”。**必须实现 C2 的“零交集 + 回退到头部信息带”算法**，而不是简单 `card.top + gap`。
2. **浮窗挂在 `ScrollView` 内部 / 与滚轮事件冲突。** 挂内层会被裁剪且随滚动跑位；挂外层后若浮窗内再嵌滚动，滚轮会被内层吃掉。**正解：浮窗挂页面级 `FloatLayout` 顶层 + `on_scroll_start` 隐藏 + 文案控制在不需内滚的行数内。**

> 补充第三条易错：**别去 i18n 找 `sk_name_*`**——技能名在 `ui_hud.SKILL_I18N`，`sk_full_*` 只放四段正文；数值行保留“代码现算”，不要写进 i18n。
