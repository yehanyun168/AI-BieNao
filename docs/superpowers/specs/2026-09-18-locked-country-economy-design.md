# 未解锁国家经济口径修复：设计规格

**状态：**书面规格已获用户确认；实施计划见 `docs/superpowers/plans/2026-09-18-locked-country-economy.md`。
**基线：**`main` 提交 `3eb73f3`；在独立分支 `codex/locked-country-economy` 实施。
**范围：**仅修复未解锁国家下载量、全球进度、预览和旧档迁移；技能施放覆写/持续效果属于下一份独立规格。

## 目标与已确认事实

玩家未解锁的国家不应产生下载，也不应推动全球渗透或结局。当前 `engine.tick_one_round` 在解锁判定失败后仍执行基础增长（`demo/engine.py:318-360`），`PlayerState.total_downloads_m` 又汇总所有国家（`:104-110`）。无头复现中，初始锁定的 JP 在第 1 周期从 0 增至 0.196692M。国家解锁时直接重置为 `UNLOCK_SEED_DOWNLOADS_M`，旧存档里已累积隐藏下载可能令总量倒退。

新的不变量：

1. **进行中的对局：**`unlocked=False` 的国家 `downloads_m=0`；它不获得周期增长、不产生偷算力、不计入全球下载/渗透/结局和委托增量。
2. **解锁事件：**只在成功解锁的当期将该国下载设为配置的解锁种子值，记录解锁事件；当期不再叠加常规增长。解锁不会单独使全球下载下降。
3. **预览：**`preview_skill`、`preview_next_cycle` 至少在“锁国不增长、不计入总量、解锁种子、单周期解锁数量上限”上与真实 tick 一致。其他已知预览/结算差异不在本包修复，未验证的精确预览仍不得作为发布承诺；上一轮 A 包的 UI 止损另行整合。
4. **已完成存档：**不撤销 `game_over`、`ending_id` 或已得成就。旧结局统计若按新的全局口径重新展示，发行说明需说明口径变更；本包不伪造历史数值。

## 方案选择

已向用户展示三种方案：A“锁国不产出也不计入总量，旧档清理隐藏下载”；B“保留隐藏下载，解锁时释放”；C“保留旧行为并解释隐藏增长”。用户批准 **A**。B 会在解锁时制造进度突跳，C 与“未解锁”的界面语义和阶段 2 的锁国跳过规则相矛盾。

## 组件与数据流

### 1. 实际结算和总量

`demo/engine.py` 的阶段 1 在 `try_unlock(...)` 失败时立即进入下一国家；成功时设置解锁种子并保持现有 `continue`。`PlayerState.total_downloads_m` 改为只汇总已解锁国家，作为读档和其他调用方遇到旧脏数据时的第二道防线。所有依赖此属性的网络效应、结局、委托和 HUD 自动沿用同一口径；不另建一份全球计数状态。

### 2. 两条只读预览

`preview_skill` 与 `preview_next_cycle` 使用影子国家列表，不修改真实对局。影子总下载只从已解锁国家求和；锁国若本周期未满足邻国渗透与解锁额度，增长为 0 并跳过计算；若成功解锁，设为种子值并计入总量。本包可在现有两条函数里做最小对齐，并以参数化对照测试约束相同语义；不在这轮重写完整结算管线。

### 3. 存档 v4→v5 迁移

`demo/save_manager.py` 将 `SAVE_VERSION` 从 4 升至 5，新增单步迁移：对每个 `unlocked=False` 的国家把旧 `downloads_m` 归零；已解锁国家下载和其他状态原样保留。迁移只作用于加载的内存数据，保留原始文件直到用户下一次正常存档。迁移可重复执行且结果不再变化；v1→v5 的逐级链也必须通过回归测试，每步写入其目标版本号。

活动中的“下载冲刺”（`goal='downloads'`）委托使用旧全球下载快照；若不处理，迁移后会出现不合理的负进度。迁移时对这类**已接受且仍活动**的委托，把 `snap_downloads` 设为迁移后的已解锁总下载，把 `accepted_tick` 设为当前 `tick_count`，把 `deadline_tick` 设为 `tick_count + window`；保留目标值、奖励和其他字段。待接受、已完成或其他类型委托不变。这是一次性的公平重启，而非给旧隐藏增长记功。发行说明应提示：旧档全球下载可能下降，活动下载委托会重新计时。

加载 v5 存档时仍要校验锁国下载为零；若玩家手改或坏档违反不变量，**在内存中归零并写一条可诊断日志**，而不是拒绝整个存档或把隐藏下载计入结局。写盘仍只发生在玩家下一次正常存档时。

## 错误处理与兼容边界

- 不改国家的解锁门槛、邻接表、科技效果、随机事件和已解锁国家的增长公式。
- 不改用户已存在的 `main` 工作区、旧 A 工作树、真实存档文件或打包物。
- 读档迁移若遇到结构损坏，继续沿用 `load_ex` 的坏档原因与日志处理；不得部分写回磁盘。
- 新口径会改变成长曲线和结局分布；旧矩阵的哈希与百分比不再作为“修复后仍正确”的依据，必须重新跑固定种子矩阵并记录差异。
- “锁国下载为零”是此版本开始的状态约束；对已结束旧档只保留结局/成就事实，不重算结束判定。

## 验证与验收

1. **先红后绿的无头测试：**初始 18 个锁国连续 3 周期都为 0；锁国对 `total_downloads_m` 与 `global_penetration` 无贡献；解锁国在成功解锁当期恰获种子值；解锁前后总量不因该国重置而下降。
2. **预览对照：**同一固定状态，分别对无技能与一个已解锁技能运行只读预览，再复制状态做真实 tick；仅比较此包负责的解锁列表、锁国增长 0、种子和已解锁总量，随机阶段的差异明确排除；覆盖单周期解锁额度已满。
3. **存档迁移：**v4 夹具包含锁国隐藏下载、已解锁下载、活动/待接受下载委托和其他委托；加载后只清锁国，活动下载委托快照/期限重置且不立刻失败；原文件在显式保存前不变。v1–v4 均可逐级迁到 v5，二次迁移幂等；已结束旧档 `ending_id`/成就不变。
4. **回归与平衡：**指定 Python 3.12 跑 `verify_tables.py`（基线 38/38）、`verify_tech_tree.py`（29/29）、`test_build.py`、相关存档/边界/预览测试；在隔离工作区跑固定种子×难度×策略矩阵，记录局长、首危机、解锁曲线、7 结局分布与旧基线的差值。不把“差值非零”当测试失败，而是作为调参依据。
5. **人工边界：**至少检查一个旧档 UI 顶栏数值和下载委托剩余时间；当前版本不会直接构建/发布 exe。`git diff --check` 和代码评审无 P0/P1 未解决问题后，才进入下一项技能状态修复。

## 成功定义

在新档及迁移后的活动旧档里，任何锁国都不能偷偷推进全球目标；玩家解锁国家不会看到因“隐藏值被重置”产生的无解释进度倒退；预览与真实结算至少在这项规则上同口径，且存档/委托仍可继续。是否已经达到公开发行门槛，仍取决于下一项技能状态修复、双语教学、真人测试和新包验收。
