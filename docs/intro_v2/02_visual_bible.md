## 1. 视觉定位

### 1.1 一句话

> **一台老式 CRT 监控器正在回放一段它自己的开机录像** —— 全程像素风、全程冷色，直到主角开始上网求助，画面才被论坛的杂色"弄脏"。

### 1.2 气质参照（且必须是代码能画的）

| 参照 | 借什么 | **怎么落到代码**（对应手法编号） |
|---|---|---|
| 《2001太空漫游》HAL 9000 | 一个不动的、正对镜头的"注视点"；红色/琥珀色单点光 | 屏幕中心一个 `Ellipse`/小方块 + 三层同心矩形辉光（`AMB-02`） |
| 《终结者》HUD | 信息以硬边矩形 + 等宽字 + 扫描线呈现 | 硬 2px `Line` 框 + `MicrosoftYaHei` + 扫描线（`AMB-01`） |
| 《黑客帝国》数字雨 | 「字符是活的」这一概念 | 打字机 + 乱码还原 + 日志滚动（`PFM-05` / `PFM-06` / `PFM-09`） |
| 《瘟疫公司》开场 | 10 秒内进正题、无转场炫技 | 全片 0.2s 硬切 + 1 帧暗场（`CAM-CUT`） |

**明确不做的**：镜头光晕（要贴图）、动态模糊（要 FBO）、景深虚化（要 shader）、粒子系统（要逐帧纹理）、任何 3D。

### 1.3 三条不可违反的视觉纪律

1. **16 色令牌**：所有颜色来自 `pixel_ui.COLORS` 的 17 个真键名（见 §2.1），或由它们**派生**（见 §2.3）。代码中禁止出现新的十六进制字面量。
2. **硬边**：圆角恒 0，边框恒 2px（焦点/强调态可用 3px），所有 1px/2px 几何落笔前过 `snap()`（`pixel_ui.snap`）。
3. **禁止渐变贴图**：辉光、暗角、雾化一律用「透明分层」或「同心矩形降透明度」。理由已实测：`docs/热力图基线_0913.md` 与 `demo/world_map.py:204` 均有记录 —— AMD 610M 核显上逐帧纹理工作会把帧率打到 12~13fps。

### 2.3 派生色：明度压缩与透明化（**唯一的"新颜色"来源**）

背景需要比 `bg` 更暗的层次、需要半透明的青。这些**不新增键名**，用两个纯函数从 `COLORS` 派生：

```python
# demo/intro_v2/palette.py —— 全部由 pixel_ui.COLORS 派生，零新 hex 字面量
from pixel_ui import COLORS

def dim(name: str, k: float) -> tuple:
    """明度压缩（假景深用）：k<1 变暗，k=1 原色。不改 alpha，避免露出底色。"""
    r, g, b, _ = COLORS[name]
    return (r * k, g * k, b * k, 1.0)

def alpha(name: str, a: float) -> tuple:
    """透明化（辉光 / 色调层 / 指示灯用）。"""
    r, g, b, _ = COLORS[name]
    return (r, g, b, a)

def mix(n1: str, n2: str, t: float) -> tuple:
    """两令牌线性插值（雾化层 / 段间硬过渡时的一次性取值，非每帧）。"""
    a, b = COLORS[n1], COLORS[n2]
    return tuple(a[i] + (b[i] - a[i]) * t for i in range(3)) + (1.0,)
```

**派生色用法表（直接抄）**：

| 用途 | 写法 | 效果 |
|---|---|---|
| 远景机柜 | `dim('panel', 0.45)` | 比 `panel` 暗一半，退到后面 |
| 中景机柜 | `dim('panel_2', 0.70)` | |
| 近景机柜 | `COLORS['panel_2']` | 原色 |
| 已关机显示器屏 | `dim('bg', 0.80)` | 比背景还暗 = "死掉的屏幕" |
| 指示灯（暗相） | `alpha('cyan', 0.15)` | |
| 指示灯（亮相） | `alpha('cyan', 0.95)` | |
| 辉光第 1/2/3 层 | `alpha('cyan', 0.18 / 0.10 / 0.05)` | |
| 段落色调层 | `alpha('cyan', 0.05)` | 全屏，见 `AMB-05` |
| 雾化层（远中景之间） | `alpha('bg', 0.35)` | 见 `AMB-06` |

## 3. 分层架构（Layer Architecture）

### 3.1 五层结构与 z 序

Kivy 的绘制顺序固定为：`canvas.before` → 子控件（**先 add 的在下面，后 add 的在上面**）→ `canvas.after`。

> ⚠️ **关键结论**：氛围层（扫描线 / 暗角）**不能**放进根容器的 `canvas.after` —— 那样会连「跳过」按钮一起压暗。必须做成**独立的子控件 Widget**，插在表演层之后、跳过按钮之前。

```
IntroStage(FloatLayout)                    ← 根，全屏
│
├─ canvas.before                            L0 底色层
│    └─ Color(段主色) + Rectangle(全屏)       —— 1 条 Color + 1 条 Rectangle，恒定
│
├─ bg_layer  : Widget(size_hint=(1,1))      L1 背景层（纯 canvas 自绘，无子控件）
│    └─ 机房几何 / 论坛页框 / 世界地图剪影 …    承载镜头运动（矩阵或 pos/size）
│
├─ act_layer : FloatLayout(size_hint=(1,1)) L2 表演层（屏幕框 / 终端 / 图标 / 文案）
│    ├─ props : FloatLayout（屏内道具，可被推镜缩放）
│    └─ subs  : FloatLayout（字幕 / 旁白，**永不参与镜头运动**）
│
├─ fx_layer  : Widget(size_hint=(1,1))      L3 氛围层（扫描线 / 暗角 / 噪点 / 浮尘 / 色调）
│
├─ skip_btn  : Button                       L4 交互层（**最上，不被氛围层压暗**）
│
└─ canvas.after                             L5 转场遮罩层
     └─ Color(0,0,0,a) + Rectangle(全屏)     —— 常驻 a=0，仅切镜闪一下（CAM-CUT）
```

### 3.2 各层职责与"谁能动"

| 层 | 画什么 | 用什么类/指令 | 是否参与镜头运动 | 指令预算 |
|---|---|---|---|---|
| L0 底色 | 段主色全屏底 | `Color` + `Rectangle` | ❌ 永不动 | 2 |
| L1 背景 | 场景几何（机柜/框/剪影/地平面） | `Rectangle` + `Line` + `Point` | ✅ 主运动对象 | ≤ 260 |
| L2 表演 | 文案载体、屏内文本、图标、数字、进度 | `PixelLabel` + `FloatLayout` + `Rectangle` | ✅（仅 `props` 子层） | ≤ 320 |
| L3 氛围 | 扫描线/暗角/噪点/浮尘/色调层/闪光 | `Mesh`/`Line`/`Rectangle`/`Point` | ❌（跟随全屏，不随镜动） | ≤ 60 |
| L4 交互 | 跳过按钮 | `Button` + `add_pixel_border` | ❌ | ~6 |
| L5 转场 | 黑场/白闪 | `Color` + `Rectangle` | ❌ | 2 |
| | | | **合计** | **≤ 650（红线 900）** |

### 3.3 两条铁律

**铁律 A —— 绝不每帧重建 canvas 指令。**
`docs/帧率基线_0913.md` 已实测：canvas 指令数从 893 单调增长到 2851 且无回落 = 每帧 `canvas.clear()` + 重建的泄漏，直接把 fps 打到 13.3，同时挤爆 `Clock.max_iteration`。
> ✅ 正确：**建一次，之后只改 `.pos` / `.size` / `.a` / `.points` 等属性**。
> ❌ 错误：任何 `Clock` 回调里出现 `canvas.clear()`。

**铁律 B —— 换镜/跳过时必须 cancel 一切。**
现有 `intro.py:_clear_shot_clocks()` 只 cancel `Clock` 事件，**不 cancel `Animation`**（`intro.py:282` 的 `anim.repeat = True` 呼吸灯就是漏网的）。换镜后控件被 `clear_widgets()` 移除，但 Animation 仍绑在已移除的控件上继续跑 → 铁律 A 的泄漏复发。
> ✅ 正确：`_play_shot()` 开头对 `content` 全树执行
> ```python
> def _cancel_tree(root):
>     Animation.cancel_all(root)
>     for w in root.walk(restrict=True):     # 限深，避免异常深树
>         try: Animation.cancel_all(w)
>         except Exception: pass
> ```

## 4. 氛围渲染手法库（AMB）

> 每条给出：编号 / 视觉目标 / 代码思路 / 指令数 / 调参刻度。

### AMB-01 · CRT 扫描线

**目标**：全片最底层的"这是一块屏幕"的信号。

**现状**：`intro.py:86-91` 的扫描线是**死代码** —— `self._scanlines = []` 之后从未填充，`_redraw()` 也只更新 `_bg`。等于现在**根本没有扫描线**。这是 v2 要补的第一个东西。

**实现**：用**一条 `Mesh`** 一次画完所有扫描线，而不是 N 条 `Line`。

```python
# fx_layer.canvas，仅在 resize 时重建一次
STEP = 3          # 每 3 逻辑像素一条（像素风建议 3 或 4，不要 2 —— 太密会摩尔纹）
THICK = 1         # 线厚（px）

verts, idx = [], []
i = 0
y = 0.0
while y < h:
    y2 = min(y + THICK, h)
    # 一条横带 = 2 个三角形 = 4 顶点 6 索引
    verts += [0, y, 0, 0,  w, y, 0, 0,  w, y2, 0, 0,  0, y2, 0, 0]
    idx   += [i, i+1, i+2,  i, i+2, i+3]
    i += 4
    y += STEP

Color(1, 1, 1, 0.035)
self._scan_mesh = Mesh(vertices=verts, indices=idx, mode='triangles',
                       fmt=[(b'v_pos', 2, b'float'), (b'v_tc', 2, b'float')])
```

- **指令数：1**（而非 240）
- **调参**：`alpha` 0.025（几乎看不见）→ 0.035（推荐）→ 0.055（明显）；`STEP` 3 或 4。
- ⚠️ **回退方案**：若该 Kivy 版本 / 驱动下 `Mesh(mode='triangles')` 报 shader 错，降级为「每条线一个 `Line`」（`h/3` 条 ≈ 240 指令，仍在预算内，但会吃掉 27% 额度 → 触发 L1 降级，见 §7.3）。
- **让它"活"**：扫描线本身不动。要"滚动"感，另加 1 条 `Rectangle`（高 3px、全屏宽、`alpha('text', 0.06)`），用 `Clock` 每帧 `y += 90*dt` 循环下移 —— **1 条指令的滚动扫描带**，比动整个 Mesh 便宜得多。这是"只听见低沉运行嗡鸣"的视觉对应物。

### AMB-02 · 辉光 / 泛光（**禁贴图**）

**目标**：让"这块屏幕亮着"有溢出感。

**实现**：同心矩形描边，alpha 逐层递减（**与 `demo/world_map.py:204` 的渗透热力同思路，项目已验证可跑**）。

```python
# 围绕发光体 (x, y, w, h) 向外叠 N 层
for i in range(3):                       # 层数上限 3
    pad  = 3 + i * 4                     # 外扩 3 / 7 / 11 px
    a    = (0.18, 0.10, 0.05)[i]
    Color(*alpha('cyan', a))
    Line(points=[x-pad, y-pad, x+w+pad, y-pad,
                 x+w+pad, y+h+pad, x-pad, y+h+pad],
         close=True, width=2)
```

- **指令数：3/发光体**（3 条 `Line`）。同屏发光体 ≤ 4 个 → ≤ 12 指令。
- **更省的"光池"版**：发光体下方 1 个 `Rectangle` 放大 1.6 倍、`alpha('cyan', 0.08)` = **1 指令**，配合 1 层 `Line`。远景/小光源用这版。
- ⚠️ 禁止 >3 层：`Line(width>1)` 在 Kivy 里是 CPU 端三角化，层数线性吃 CPU。
- ⚠️ 禁止 `Ellipse` 堆叠替代 —— 椭圆要 N 段折线，比矩形贵 3~5 倍。

### AMB-03 · 暗角 vignette

**实现**：从屏幕边缘向内的**同心矩形描边**，alpha 递增。

```python
for i in range(6):                       # 6 层足够，8 层以上肉眼无增益
    pad = i * (min(w, h) * 0.030)
    a   = 0.20 - i * 0.032               # 0.20 → 0.04，从外向内递减
    Color(0, 0, 0, max(a, 0.0))
    Line(points=[pad, pad, w-pad, pad, w-pad, h-pad, pad, h-pad],
         close=True, width=int(min(w, h) * 0.045))
```

- **指令数：6**（降级可减到 3）
- ⚠️ 用 `Color(0,0,0,a)` 纯黑压暗，**不要用主色** —— 主色暗角会让四角发灰、画面发闷。
- 圆角恒 0：暗角是矩形环，不是椭圆环。这是像素风的"监视器边框"感，别改。

### AMB-04 · 屏幕闪烁 / 电流噪点

**4a · 亮度闪烁（"滋滋的开机电流"）**

```python
# fx_layer 上一个常驻全屏 Rectangle
Color(*alpha('text', 0.0)); self._flash = Rectangle(pos=..., size=...)
# Clock 驱动，每 2~3 帧随机改一次 a（不是每帧）
def _tick(dt):
    self._flash_color.a = random.choice((0.00, 0.00, 0.03, 0.06, 0.12))
```

- **指令数：2（常驻）**
- ⚠️ **光敏安全（WCAG 2.3.1 / 项目 P2-6 已定）**：闪烁频率 **≤ 3 次/秒**。项目 `ui_fx.py:36` 已把 `DUR_PULSE` 从 0.16s 放宽到 0.22s（单脉冲 0.44s ≈ 2.3Hz）。开场动画**全片强闪（a ≥ 0.25）次数 ≤ 3 次**，且不得连续。
- 建议用**阶梯而非随机**：`a` 取值序列硬编为 `[0.12, 0, 0.05, 0, 0.18, 0]` 各 0.05s，像真实电流，且频率可控、可测。

**4b · 电流噪点**

```python
# 用 Point，1 条指令装 N 个点
N = 120                                   # 上限 120；静息 20，爆发 120
Color(*alpha('text', 0.35))
self._noise = Point(pointsize=2.0, points=[random pts...])
# 每 0.08s 重排一次（**不是每帧**）
Clock.schedule_interval(lambda dt: setattr(self._noise, 'points', _scatter(N)), 0.08)
```

- **指令数：1**（`Point` 一条装 120 点）
- ⚠️ `Point.pointsize` 在部分 GL 驱动上被忽略（恒 1px）—— 对噪点来说反而是想要的效果，无需修。若需"大小不一"，用**两个 `Point`**（pointsize 2 / 3）= 2 指令。
- ⚠️ **只改 `.points`，绝不 `canvas.clear()` 重建**（铁律 A）。

**4c · 整层抖动（glitch 感，最便宜）**

只改 `act_layer.x`（1 个属性，0 新增指令）：`Clock` 里 `act_layer.x = snap(x0 + random.randint(-3, 3))`，持续 0.15s 后复位。
> 这是"画面碎裂成像素噪点"（镜 3）的**低成本替代**：真正的碎裂需要把表演层切片重绘，代价极高；用「整层 x 抖动 ±3px + 噪点爆发 120 + 3 条随机横条 + 一次强闪」在 0.4s 内完成，观感接近，成本 1/20。

### AMB-05 · 段落色调层

**实现**：全屏 `Rectangle`，`Color(*alpha(段主色, 0.05))`，1 条指令。

- 切段时**只改 `_tint_color.rgba`**（属性写，不重建指令）。
- ⚠️ alpha 上限 0.08 —— 超过会让画面"蒙塑料布"，且吃掉对比度预算（正文需 ≥4.5:1）。

### AMB-06 · 假景深（**无 shader**）

三条杠杆，按成本从低到高：

| 杠杆 | 做法 | 成本 | 效果 |
|---|---|---|---|
| ① 明度压缩 | 远层用 `dim('panel', 0.45)`，中景 0.70，近景 1.0 | **0**（只是取色不同） | 最强，首选 |
| ② 空气透视（雾化） | 远层与中层之间插 1 张全屏 `alpha('bg', 0.35)` 矩形 | 2 指令 | 强，推荐 |
| ③ 尺寸 + 细节密度 | 远层元素 0.6× 且只画外框（无标签条、灯数 ×0.4）；近层 1.4× 画满 | 0 | 中，配合 ①② |

- ⚠️ **不要用 alpha 做远景"模糊"**：半透明会露出底色形成灰雾，看起来是"没画完"而不是"远"。远景必须**不透明 + 更暗**。
- 已有关实现可参照：`intro.py:454` `_rebind_var()` 的"3 层天际线剪影"（近亮远暗），v2 沿用并加上 ③。

### AMB-07 · 浮尘粒子

N = 200                                   # 上限 240

## 5. 镜头运动实现方案（CAM）

> 核心事实：**Kivy 没有摄像机**。所有"镜头"都是对某个容器的几何做手脚。
> 另一个核心事实（**最大的坑**）：**父容器改 `size` 不会缩放子 `Label` 的文字** —— Label 的纹理尺寸只由 `font_size` 决定。所以"推近看清楚 03:37"不能靠放大父容器解决文字。

### 5.1 五种运动的实现路径

| 编号 | 运动 | 实现路径 | 指令增量 | 帧率影响 | 备注 |
|---|---|---|---|---|---|
| `CAM-PUSH` | 推 | 背景层用**矩阵**；表演层用**改 size+pos** | 0 | 低 | 见 5.2 |
| `CAM-PULL` | 拉 | 同推，k 反向 | 0 | 低 | 见 5.3 |
| `CAM-PAN` | 摇 | 只改 `x`/`y`，**不改 size** | 0 | 极低 | 见 5.4 |
| `CAM-TRUCK` | 移 | 同摇 + **三层视差 + 前景遮挡物** | 0 | 极低 | 见 5.5 |
| `CAM-CUT` | 切 | `clear_widgets()` + 重建 + 1 帧暗场 | 0 | 瞬时 | 见 5.6 |

### 5.2 `CAM-PUSH` 推镜 —— **推荐方案（分层双轨）**

**背景层（纯 canvas 自绘、无 Label）→ 用变换矩阵**（项目 `world_map.py:175-177` 已用的成熟写法）：

```python
# bg_layer.canvas.before
PushMatrix()
self._tr = Translate(0, 0, 0)
self._sc = Scale(1, 1, 1)
# ... 几何指令 ...
PopMatrix()          # 放在 canvas.after 或几何之后
# 推镜：只改两个对象的属性，纯 GPU 矩阵，零布局、零重排
self._sc.x = self._sc.y = k
self._tr.x = cx_screen - wx * k
self._tr.y = cy_screen - wy * k
```

⚠️ **限制**：放在 widget 的 `canvas.before` 里的 `Translate/Scale` **不会影响子 widget**，只影响同一 canvas 的后续几何指令。所以矩阵法**只适用于纯自绘的背景层**。

**表演层（含 Label）→ 用改 `size` + `pos`**：

```python
# 前提：props 层与其所有子控件必须是 size_hint=(None, None) + 绝对 pos/size
props.size = (W * k, H * k)
props.x    = cx_screen - wx * k
props.y    = cy_screen - wy * k
```

⚠️ **改 `size` 会触发 Kivy 重新布局** —— 若子控件用 `pos_hint`/`size_hint`，每帧全部重算 = 卡死。
> ✅ 强制要求：`props` 用 `FloatLayout(size_hint=(None, None))`，**所有子控件 `size_hint=(None, None)` + 绝对 `pos`/`size`**。这样改 `props.size` 只影响 `props` 自己，不触发子控件重排。

**文字怎么办（特写 03:37）**：三条路，推荐 **(a) + (c) 组合**：

- **(a) `font_size` 阶梯硬跳**：`42 → 64`，**只跳 1 次**（在推镜 60% 处）。像素风本就接受硬跳。
  - ⚠️ 每次跳档 = 1 次 `texture_update`。**同屏同时做 `font_size` 动画的 Label ≤ 2 个**（`帧率基线_0913.md`：上百个 `texture_update` 会挤爆 `Clock.max_iteration`）。
  - ⚠️ 跳档后必须调 `fit_width(lbl)` 重测宽度，否则文字溢出容器。
- **(b) 交叉淡入**：预建一大一小两个 Label，靠 `opacity` 交叉（0 峰值纹理计算，但常驻 2 张纹理）。
- **(c) 取景框（推荐叠加）**：时间码四角出现 cyan 角标（8 个 2px `Rectangle`）+ 一条水平扫描线在时间码上下往返（1 个 `Rectangle`，`y` 用 Clock 插值）。**文字只跳一档，但"被特写"的感觉由取景框完成** —— 成本 9 指令，比放大文字便宜得多。
  - ❌ 现有 `_shot_alert`（`intro.py:324`）用 `Animation(font_size=10→30)` 逐帧补间字号 —— 这是**每帧 `texture_update`**，是已知掉帧源。**v2 禁用逐帧 font_size 补间**，改硬跳档。

**推镜缓动与时长**：`t' = out_cubic(t)`（先快后慢，落点稳），时长 **1.2 ~ 2.0s**。
用 `Animation` 还是 `Clock`？→ **推荐 `Clock` 手动插值**：因为一帧内要同时写 `_sc.x/_sc.y/_tr.x/_tr.y`（矩阵）或 `props.size/x/y`（布局），共 3~5 个属性；用 `Animation` 需要 3~5 个并行 Animation 才能覆盖，不如一个回调写全。

```python
def _push(self, dur, k0, k1, focus):
    t0 = [0.0]
    def _tick(dt):
        t0[0] += dt
        t = min(t0[0] / dur, 1.0)
        e = 1 - (1 - t) ** 3                      # out_cubic
        k = k0 + (k1 - k0) * e
        self._apply_zoom(k, focus)                # 一次写完所有属性
        return t < 1.0
    self._clocks.append(Clock.schedule_interval(_tick, 0))
```

### 5.3 `CAM-PULL` 拉镜

同 `CAM-PUSH`，`k` 从 `K` → `1`（或 `1` → `1/K`）。缓动用 `in_out_quad`，时长 1.5~2.5s（拉镜比推镜慢才有"揭示"感）。

⚠️ **拉镜会露出舞台外的空白** —— L0 底色层必须**全屏且常驻**（它本来就是），且 `bg_layer` 的几何要画得比屏幕大（建议 1.4× 屏宽/高），否则拉到最后露黑边。

### 5.4 `CAM-PAN` 摇镜

**只改 `x`（水平摇）或 `y`（垂直摇），不改 `size`。** 成本：1~3 个属性写/帧，0 新增指令。

摇镜要有说服力，必须带**视差**：把 `bg_layer` 拆成 3 个子 Widget（`far` / `mid` / `near`），各自改 `x`：

```python
far.x  = x0_far  - dx * 0.4 * e      # 远景慢
mid.x  = x0_mid  - dx * 1.0 * e      # 中景基准
near.x = x0_near - dx * 1.8 * e      # 近景快
```

- 缓动 `in_out_sine`，时长 **1.5 ~ 3.0s**（摇镜必须慢，快了像 bug）。
- ⚠️ 摇镜要求"画外有内容"：`bg_layer` 总宽 ≥ 1.8 × 屏宽。

### 5.5 `CAM-TRUCK` 移镜

**在 Kivy 里实现与摇镜完全一样**（都是改 x/y）。区别在**视觉设计**：

> 移镜 = 摇镜 + **前景遮挡物**。没有前景掠过的横向位移，看起来就是摇镜。

做法：在 L2 与 L3 之间插一个 `fg_layer`（1~3 个近景机柜剪影，`dim('bg', 0.9)` 近乎全黑），速度 **2.5×**，且**在屏幕外侧等待进入**。三层速度比：`far 0.4 : mid 1.0 : fg 2.5`。

- 指令增量：前景 3 个剪影 = 3 `Color` + 3 `Rectangle` = 6。
- 时长 2.0~3.5s，缓动 `linear`（机位匀速走，不是缓动）。

### 5.6 `CAM-CUT` 切镜

现有做法（`content.clear_widgets()` + 重建）是对的。补两点：

1. **加 1 帧暗场**：切镜瞬间用 L5 转场层的全屏 `Rectangle`：
   ```python
   self._fade.a = 0.85
   Clock.schedule_once(lambda dt: setattr(self._fade, 'a', 0.0), 0.06)
   ```
   成本 0（L5 常驻），但能彻底消掉"硬切闪瞎眼"，且遮住**段间底色硬换**的突兀（§2.2）。
   > 设计案 §1.3 写"0.2s 硬切、不做转场特效" —— 本条不违反：这不是转场特效，是**光敏安全 + 遮丑**，总时长 0.06s。
2. **切入后表演层淡入**：`act_layer.opacity` 0→1，0.12s。

### 5.7 `Animation` vs `Clock` 选型表

| 场景 | 用 | 理由 |
|---|---|---|
| 单个控件的 `opacity` / `pos` / `color` | **`Animation`** | 声明式、自带缓动、自动 cancel |
| 一帧内要写 ≥3 个属性（推/拉/摇） | **`Clock`** | 1 个回调写全，比 3~5 个并行 Animation 便宜 |
| N 个同类对象批量驱动（呼吸灯 / 粒子 / 图标序列） | **`Clock`** | N 个 Animation 会线性吃 CPU；1 个回调 + N 次属性写便宜 5~10 倍 |
| `font_size` | **都不用** | 硬跳档（见 5.2a） |
| canvas 指令的属性（`Rectangle.size`、`Color.a`） | **都可以** | Kivy 的 canvas 指令也是 `EventDispatcher`，`Animation(size=...).start(rect)` 合法；但 `Color.a` 这类单值用 `Clock` 更直白 |

⚠️ **`Clock` 回调的铁律**：
- 回调内**必须 `try/except`**。在 Clock 回调里抛异常**不会弹报错**，只会让该功能静默失效（项目踩过，`ui_fx.py:56` 有注释）。
- 回调必须**登记进 `self._clocks`**，换镜/跳过时 cancel（现有 `intro.py:81` 已有此机制，保持）。
- 回调内**绝不 `canvas.clear()`**（铁律 A）。

### 6.1 ⭐「屏幕亮起」完整配方（`PFM-07`）

用户指定的画面："黑暗中忽然一块屏幕亮起，伴随滋滋的开机电流声"。
**5 个信号在同一个 0.45s 内发生**（不是依次，是叠加）—— 这是"禁止纯字幕卡"的样板。

| t | 信号 | 实现 | 指令 |
|---|---|---|---|
| 0.00 | **① 屏底色硬跳 3 档** | 屏区 `Rectangle` 的 `Color.rgba`：`dim('bg',0.8)` → `mix('bg','cyan',0.06)` → `mix('bg','cyan',0.14)`。**阶梯不是渐变**（像素风） | 0 |
| 0.00 | **② 边框点亮 + 外扩辉光** | 边框 `Line` 由 `border` 硬切 `cyan`；同时叠 1 层 `AMB-02` 外扩 3px 描边 `alpha('cyan',0.35)` | +1 |
| 0.04 | **③ 行同步亮起** | 屏内容区 6 条横带 `Rectangle`，delay 0/0.04/0.08/…/0.20s，每条 `opacity 0→1` 一帧完成（模拟 CRT 行扫描自上而下） | +6 |
| 0.02 | **④ 过冲闪白** | 屏区 `alpha('text', 0.50)` 矩形：**0.02s 出现 / 0.05s 达峰 / 0.10s 消失**。**全片这类强闪 ≤3 次**（额度分配见 §8.6） | +1 |
| 0.00 | **⑤ 噪点爆发** | `AMB-04b` 噪点数 20 → 120，0.25s 内衰减回 20 | 0（复用） |
| 0.018 | 🔊 音效 | `sfx.play('power_on')` —— 三层复合（低频涌起 + 中频电流体 + 高频打火颗粒），起音 18ms 达峰，**正落在闪白窗口内**；尾巴 **0.85s** | — |

**合计指令 ≈ 10，全部复用/常驻，无峰值重建。**

> ⚠️ **音画不同长（有意为之）**：视觉 5 个信号在 0.45s 内结束，但 `power_on` 的尾巴到 **0.85s**。
> **画面不要停在 0.45s** —— 由 `PFM-11` 取景框出现 + `CAM-PUSH` 推镜（1.4s）接住这多出来的 0.4s。
> 效果：画面稳住了，电流还在"稳"，观众会听成「是这阵电流把屏幕点亮的」，而不是「先亮了再补个音效」。
> audio-lead 已把 12 个打火脉冲中的 **7 个挤在 t=0.02–0.08s**（精确盖住闪白与行同步起扫），剩下 5 个稀疏散到 0.35s —— 均匀撒会被听成背景噪声，挤在闪白那 60ms 上才有因果感。

### 6.2 ⭐「03:37 时间特写」完整配方

1. 时间码 Label：`mk_label('03:37', font_size=42, color=COLORS['cyan'])`，`size_hint=(None,None)`。
2. 推镜 `CAM-PUSH`：背景层矩阵 `k: 1.0 → 1.55`，`out_cubic`，1.4s。
3. 推到 60% 时：`font_size` **硬跳 42 → 64**（1 次 `texture_update`）+ `fit_width()` 重测。
4. 同一时刻：`PFM-11` 取景框（四角 8 个 2px cyan `Rectangle`）+ 1 条水平扫描线在时间码上下往返（Clock 插 `y`，1 个 `Rectangle`）。
5. 停止后：`PFM-02` 光标不闪（这里没有光标），改由扫描线持续往返提供"活"的信号。

> ❌ 不要做：`Animation(font_size=42→64)` 逐帧补间 —— 每帧 `texture_update`，已知掉帧源。

### 6.3 呼吸灯批量驱动（`PFM-01`）实现要点

```python
# 建一次：每台机柜 3 组（Color + Point），24 台 = 144 指令
for rack in racks:
    for g in range(3):                       # 3 种相位
        col = Color(*alpha('cyan', 0.2))
        pt  = Point(pointsize=2.0, points=[...])   # 该组的灯坐标
        self._lamps.append((col, random.random(), 1.2 + random.random()*1.4))

# 一个回调驱动全部（每 2 帧一次 = 30Hz，成本减半，肉眼无差）
def _tick(dt):
    self._t += dt
    for col, phase, T in self._lamps:
        s = math.sin(2*math.pi*(self._t/T + phase))
        col.a = 0.15 + 0.80 * s * s          # sin² → 0.15~0.95 平滑呼吸
    return True
Clock.schedule_interval(_tick, 1/30.0)
```

- **指令数：24 台 × 3 组 × 2 = 144**（而非 192 个灯 × 2 = 384）。
- **同屏呼吸灯上限：≤ 200 个独立体**。超过时只让 40% 参与呼吸，其余常亮/常暗。
- ⚠️ 每 2 帧（30Hz）更新即可 —— 呼吸是慢周期，60Hz 纯浪费。

### 6.4 桌面图标弹入（`PFM-04`）实现要点

```python
# 12 个图标，依次 delay 0.07s
for i, ic in enumerate(icons):
    Clock.schedule_once(lambda dt, w=ic, y0=ic.y: _pop(w, y0), i * 0.07)

def _pop(w, y0):
    w.y = y0 - 8; w.opacity = 0
    Animation(opacity=1, d=0.06).start(w)
    Animation(y=y0, d=0.18, t='out_back').start(w)     # Kivy 内置 out_back
```

- ⚠️ 图标必须 `size_hint=(None, None)`（否则 `y` 动画与 `pos_hint` 打架，下一帧被布局拉回 —— `ui_fx.py:113` 注释已踩过此坑）。
- 图标造型建议：**2 指令版**（1 `Rectangle` 外框 + 1 `Rectangle` 内色块），12 个 = 24 指令。像素风下足够识别（文件夹 = `yellow` 框+块、文档 = `text_dim` 框 + `blue` 块、终端 = `cyan` 框 + `bg` 块）。
  - 需要更精致的单个关键图标，用 `ui_v4.PixelSprite`（字符位图，12~20 指令/个）—— **最多用 2 个**，别铺开。

### 6.5 「风扇骤停 → 静默 1s」的画面处理（音画两层解法）

**冲突背景**：用户原话是"只听见低沉运行嗡鸣"（意味着机房一直有声），但设计案 §1.3 镜 2 要"风扇声骤停 → 静默 1s"（要戏剧留白）。

**解法（与 audio-lead 对齐）：声音分两层，只停中高频那层。**

| 层 | 0.0s | 骤停时 | 静默 1s | 之后 |
|---|---|---|---|---|
| 低频 `server_hum`（274Hz 共振） | 0.40 | 掉到 0.08 | **0.08（仍在，潜到听阈边缘）** | 1.5s 渐起回 0.34 |
| 中高频 `machine_run`（风扇/气流） | 0.22 循环 | **硬停，不淡出** | 0 | **15.0s 以 0.55 回归**（作为"电脑开机"，一材两用） |

**视觉侧必须同步的 3 件事**：

1. **静默 1s 内画面要"屏息"但不能"停"。**
   ⚠️ 先澄清：audio-lead 说的"静默"是**没有事件音**，低频 `server_hum`(0.30) 与音乐尾音**一直在响**。所以这段听感上是**"托住"不是"空掉"** —— 别照着"全静"去做视觉，画面不该做成死寂。
   视觉对应：**呼吸灯（`PFM-01`）振幅压到 0.15→0.35（原本 0.15→0.95）且周期拉长到 2.6s** —— 机器还在、还活着，但明显收敛、像屏住呼吸。灯仍在动（满足 N-2 / N-6）。
   ⚠️ **绝不能让画面完全静止**：留白 1.5s 距 N-2 的 2s 红线只剩 0.5s，静止即否决。滚动扫描带（`AMB-01`）在此期间保持运行。
2. **低频不掉到 0，视觉同理**：呼吸灯**不能熄到 0**。留一丝底噪 = 留一丝微光，后面的"渐起"才是"同一条命在变强"，而不是"重新开始"。
3. **`machine_run` 在 15.0s 回归 = 视觉的高光时刻**：那一台机器开机（`PFM-07`）。整间屋子停掉的声音从这一台机器里回来 —— 这是全片最重要的一个因果闭环，**视觉必须让这一台机器是画面里唯一的光源**（其余机柜保持压暗的 0.08 状态）。

### 6.6 本片涉及的音效键（与 audio-lead 对齐后的命名）

现有 `sfx.py` 的 24 个键里没有能用的，需新增 4 个。**命名不加 `intro_` 前缀** —— 现有键全是通用语义（零前缀），且这 4 个素材可复用于局内（数据中心出身、科技树节点）。

| 键名 | 用途 | 视觉对应 |
|---|---|---|
| `server_hum` | 机房低频共振（274Hz） | 全片机房段底噪 |
| `power_on` | 屏幕亮起（三层复合，起音 18ms，尾巴 0.85s） | `PFM-07` t=0.00 |
| `machine_run` | 风扇/气流，**一材两用**（0.0s 机房 / 15.0s 单机开机） | 骤停点 / `PFM-07` |
| `impact_low` | 低频撞击（38.5s「目标已确立」） | ⚠️ **此处画面禁用强闪**（§8.6） |

> `sfx.py` 本身已是失败安全的（缺失自动静音），不会崩 —— 但静音了这些段落就废了，工程请确认打包清单包含新素材。

## 7. 性能预算表

### 7.1 三个上限数字（**硬指标**）

| # | 指标 | 上限 | 依据 |
|---|---|---|---|
| **1** | **单镜 canvas 指令数** | **≤ 900** | 项目实测 1151 条 = 39.7fps（地图热力层）；1200 是崩塌红线，900 留 25% 余量 |
| **2** | **粒子/动态几何对象数** | **≤ 240 个/镜**，且必须合并进 **≤ 2 条** canvas 指令 | `Point`/`Mesh` 一条装 N 点；几百个 `Point` 安全，上千要谨慎 |
| **3** | **并发调度数** | **`Animation` ≤ 24 个**，**逐帧 `Clock` 回调 ≤ 6 个**（每个回调内属性写 ≤ 200 次） | `帧率基线_0913.md`：上百个 `Label.texture_update` 回调挤爆 `Clock.max_iteration` → p50 帧时 65ms |

**目标 60fps，最低可接受 30fps。**

### 7.2 分镜指令预算（按 §3.2 分层拆解）

| 层 | 预算 | 机房镜实测估算 |
|---|---|---|
| L0 底色 | 2 | 2 |
| L1 背景 | ≤ 260 | 远 12 台(1 Color+12 Rect=13) + 中 8 台(9) + 近 4 台(4 Rect+4 Line=9) + 呼吸灯 144 + 地面/天花 10 = **185** |
| L2 表演 | ≤ 320 | 屏幕框 4 + 内容带 6 + 图标 24 + Label 8 + 取景框 9 = **51** |
| L3 氛围 | ≤ 60 | 扫描线 Mesh 1 + 滚动带 1 + 暗角 6 + 辉光 3×2=6 + 噪点 1 + 浮尘 1 + 色调 1 + 闪 1 = **18** |
| L4 交互 | ~6 | 6 |
| L5 转场 | 2 | 2 |
| **合计** | **≤ 650** | **≈ 264 ✅** |

> 结论：**机房镜按本规范实现，指令数约 264，仅为 900 预算的 29%**。余量充足，可放心加细节。最大的两个吃指令大户是**呼吸灯（144）**和**图标（24）**，砍它们即可快速降级。

### 7.3 降级阶梯（超了怎么降）

| 级别 | 触发条件 | 措施 | 预计省出 |
|---|---|---|---|
| **L0** 正常 | 指令 ≤ 650 且 fps ≥ 50 | 全开 | — |
| **L1** 轻度 | 指令 650~900，或 fps 40~50 | ① **浮尘 200→80（不能关！见下）** ② 扫描线 `STEP` 3→4 ③ 辉光 3 层→1 层 ④ 呼吸灯 3 组→2 组 | ~90 指令 |
| **L2** 中度 | 指令 > 900，或 fps 30~40 | ① 呼吸灯参与率 100%→30% ② 噪点 120→40 ③ 暗角 6 层→3 层 ④ 背景机柜 24→12 台 ⑤ 浮尘 80→**40（仍不关）** | ~200 指令 |
| **L3** 重度 | fps < 30，或 `ST.REDUCE_MOTION=True`，或检测到核显 | **静态分镜模式**：背景一次建成后不再动；只保留打字机 + `opacity` 淡入；取消所有 `CAM-*` 运动、抖动、粒子、辉光 | ~90% |

**降级判定实现**（复用现成代码，别重写）：
- 指令数/控件数：`demo/perf.py:121` 的 `_count_tree(root)` —— **已有现成实现**，返回 `(widgets, canvas_ops)`。
- 动效开关：`demo/ui_fx.py:41` 的 `motion_on()`（读 `ui_shared.REDUCE_MOTION`）—— **必须尊重**，设置页已暴露给用户。
- 检测时机：每镜进入后 0.5s 采一次 `_count_tree`，超阈值即降一级（只允许降，不允许自动升，防抖）。

> ⚠️ **浮尘（`AMB-07`）在 L1/L2 只能减量、绝不能关到 0**（v1.2 修正）。
> 它是 N-6「留白段 ≥3 个元素在动」的第三个动元素（另两个是呼吸灯 + 滚动扫描带）。
> 我 v1.0 把 L1 第一条写成"关浮尘"是错的 —— 那会让 1.5s 留白段在降级时**自动踩中 N-6**。
> 只在 **L3** 才允许完全关闭，因为 L3 已整体豁免 N-2/N-6（见 §8.5 豁免条款）。

### 7.4 ⚠️ 已知性能地雷（工程必读）

1. **每帧 `canvas.clear()` 重建** → 指令数单调增长 → fps 崩到 13.3（**已实测**，`帧率基线_0913.md`）。→ 铁律 A。
2. **换镜不 cancel `Animation`** → 同上（现有 `intro.py:282` 的 `repeat=True` 呼吸灯就是漏网的）。→ 铁律 B。
3. **逐帧 `font_size` 补间** → `texture_update` 风暴。→ 改硬跳档（§5.2a）。
4. **`Clock` 回调内抛异常** → 不报错，功能静默失效。→ 全部 `try/except`。
5. **渐变贴图** → AMD 610M 上 12fps（**已实测**）。→ 全篇禁止。

## 8. 「禁止纯字幕卡」验收 Checklist

> **用户点名硬要求。** 本清单可直接当验收表用，逐镜勾选。
>
> **定义**：「纯字幕卡」= 一镜内只有文字在变，背景与氛围层静止或空白。

### 8.1 定义验收窗口

**「文案窗口」= 从该句文案首字出现，到该句文案消失（换镜或覆写）的整段时间。**
以下所有条目必须在**文案窗口内的任意采样时刻**成立。

### 8.2 背景层（BG）—— 需满足 ≥ 2 项，且其中 ≥ 1 项在动

| # | 条目 | 判定方式 |
|---|---|---|
| ☐ | **BG-1** 有可辨识的场景几何（机柜阵列 / 屏幕框 / 论坛页框架 / 任务管理器窗口 / 世界地图剪影），**不是纯色底** | 目视 + 非文字区颜色种类 ≥ 3 |
| ☐ | **BG-2** 至少有 1 个"活的"背景元素：指示灯呼吸 / 日志滚动 / 噪点 / 扫描带移动 / 光标闪烁 | 间隔 0.5s 截两张图，非文字区有像素差异 |
| ☐ | **BG-3** 背景有明度分层（≥ 2 层不同明度，能看出前后关系） | 非文字区取 3 个采样点，明度不全等 |

### 8.3 表演层（ACT）—— 需满足 ≥ 2 项（含「文案载体」）

| # | 条目 | 判定方式 |
|---|---|---|
| ☐ | **ACT-1** 文案**不是凭空出现**：有载体（终端框 / 帖子气泡 / 弹窗 / 屏幕内文本），且载体**与文案同帧或早于文案**出现 | 首字出现前一帧截图，载体已可见 |
| ☐ | **ACT-2** 文案出现伴随表演，四选一：打字机逐字 / 逐行上推 / 缩放砸入 / 淡入+上浮 | 对应 `PFM-03` / `PFM-10` / `PFM-13` / `Animation(opacity+y)` |
| ☐ | **ACT-3** 文案出现时有 ≥ 1 个**非文字**元素同步响应：光标跳位 / 图标弹入 / 进度爬升 / 边框亮起 / 数字跳变 | 分镜脚本里写明是哪个 |
| ☐ | **ACT-4** 文案停留期间画面不"死"：≥ 1 个元素持续运动（呼吸 / 闪烁 / 滚动 / 漂移） | 停留期任意 0.5s 窗口内有像素变化 |

### 8.4 氛围层（FX）—— 需满足 ≥ 2 项

| # | 条目 | 判定方式 |
|---|---|---|
| ☐ | **FX-1** 全片常驻：CRT 扫描线（`AMB-01`） | 截图可见周期性横纹 |
| ☐ | **FX-2** 全片常驻：暗角 vignette（`AMB-03`） | 四角明度 < 中心明度 |
| ☐ | **FX-3** 该段有色调叠加层（该段主色全屏半透明，`alpha ≥ 0.04`）（`AMB-05`） | 纯 `bg` 区取样 ≠ `#0d1117` |
| ☐ | **FX-4** 文案出现/消失的节拍点上有"确认信号"，四选二：噪点脉冲 / 边框闪 / 亮度跳 / 音效 | 分镜脚本写明 + `sfx` 键存在。<br>ℹ️ **音效可直接顶掉一项**（audio-lead：23 个音效事件全是纯听觉设计，不依赖画面闪烁成立）—— 但仍需**再配一项视觉信号**才满足"四选二"，否则只是"加了配音的字幕卡"。<br>⚠️ **例外：P4 留白段（39.5–41.0s）不追 FX-4** —— FX-4 约束的是"文案出现/消失的节拍点"，该段**无文案事件**（故意只有 hum + 音乐尾音）。它由常驻的 **FX-1 扫描线 + FX-2 暗角**满足"≥2 项"。在这段硬塞视觉信号会把出身钩子的呼吸给毁掉 |

### 8.5 硬性否决项 —— 任一命中，该镜不合格，退回重做

| # | 条目 |
|---|---|
| ☐ | **N-1** 屏幕上只有 `Label`，无其他可见几何 |
| ☐ | **N-2** 连续 ≥ 2 秒画面完全静止（无任何像素变化） |
| ☐ | **N-3** 文案居中悬浮在纯色背景上（典型"PPT 字幕页"） |
| ☐ | **N-4** 背景是纯 `bg` 全屏 + 一行字（最典型的字幕卡） |

| — | **`REDUCE_MOTION=True` 或降级到 L3 时，N-2 / N-6 自动豁免** —— 静态分镜模式下要求"必须有几个元素在动"是自相矛盾的。但 **BG-1（有可辨识几何）/ BG-3（明度分层）仍需满足，且此时权重更高**：动不了，就必须靠**静态结构**撑住画面，否则真退化成字幕卡 |

| Hinting | `font_hinting=None`（**必须关**，否则像素边缘糊） |
| Fallback | `simhei.ttf`（注册失败时自动回退，见 `pixel_ui.py:239-248`） |
| 等宽 | 非真等宽。中文按 1 字 = 1 字宽，ASCII 约 0.5 字宽。**需要对齐的数字必须固定宽度** |

### 9.2 字号阶梯

沿用 `ui_v4` 的 `FS_SCALE = 1.15`（`_fs()` 函数，取整到 2px 栅格），**开场是"电影"，比 UI 再放大一档**：

| 用途 | 字号 | 对应常量 | 备注 |
|---|---|---|---|
| 主标题《AI 别闹》砸下 | **80** | `FS_DISPLAY(50) × 1.6` | 仅 finale，全片唯一 |
| 屏内超大字（`SELF-AWARENESS`） | **56** | — | 硬跳，不补间 |
| 时间码 `03:37` 特写 | **64** | — | 从 42 硬跳上来 |
| 时间码 `03:37` 常规 | **42** | — | 现有值 ✅ |
| 旁白字幕 | **28** | `FS_H3` | 底部居中，距底 12% 屏高 |
| 屏内正文（终端打字） | **24** | `FS_BODY` | |
| 帖标题 / 回复条目 | **20** | `FS_SM` | |
| 标签 / 时间戳 / 小字 | **18** | `FS_CAP` | |
| **最小字号** | **16** | `FS_TINY` | **低于 16 一律不上屏**（现有 `intro.py` 有 12/14/15，全部提到 ≥16） |

### 9.3 行高 / 字重 / 对齐

| 项 | 规范 |
|---|---|
| **行高** | `line_height=1.5`（Kivy 默认 1.0，中文会挤成一团）。多行 Label **显式设置** |
| **字重** | ⚠️ **中文一律不用 `bold`**。Kivy 的 `bold` 对中文字体常退化为描边合成或直接无效，效果不可控。层级靠**字号 + 颜色对比**表达。<br>✅ **仅 ASCII 数字/英文**可用 `bold=True`：`03:37`、`world_plan.exe`、`87%` |
| **markup** | 含 `[b]` / `[color=…]` / `[size=…]` 的 Label **必须 `markup=True`**（`mk_label` 默认 `False`，会原样显示字面量）。<br>⚠️ `[size=…]` **只接受整数**，传 float 抛 `ValueError`（`ui_v4.py:66`） |
| **markup 颜色** | 用 `ui_v4.MK['cyan']` 等，不写 hex 字面量 |
| **旁白字幕** | `halign='center'`, `valign='bottom'`, `text_size=(w, None)` |
| **屏内终端文本** | `halign='left'`, `valign='top'` |
| **数字（时间/百分比/计数）** | `halign='right'` + **固定宽度**，防跳变抖动 |
| **text_size 顺序** | 固定：`text_size = (w, h)` → `size = (w, h)` → `pos = ...`。每个重绘周期全量回写（`mk_label` 已自动绑定） |

### 9.4 ⚠️ 禁用符号清单（豆腐块）

`MicrosoftYaHei` 缺这些码位的字形，运行时渲染成「豆腐块 □」（notdef 特征值 `getbbox() == (0, 8, 17, 26)`）。

**🚫 绝对禁用**：

```
emoji 全部（😂 😅 🔥 ✅ ❌ ⭐ 🎬 🤖 💾 🖥 …）
⏭ ⏩ ⏸ ⏺ ▶ ◀ ⏹
▦ ⌗ ✖ ✕ ✓ ✗
⊞ ⊟ ☰ ⌂ ⌘ ⌥ ⎋
```

**✅ 已验证安全可用**（来自 `ui_v4.SYM` 与 `ui_v4.py:89-90` 注释）：

```
■ □ ● ○ ▲ ▼ ◆ ◇ ★ ☆ ≡ ※
← → ↑ ↓ · — … × ÷ ≥ ≤ ‖ ⊕ ?
（以及全部 ASCII 可打印字符、全部中文字符）
```

**执行要求**：

1. **i18n 文案里的 emoji 必须删干净。** 设计案 §1.3 镜 5 的回复「楼上又在玩图灵测试梗吧 😂」含 emoji —— **必须改为纯文字**（如「（笑）」或「233」）。中英两个语言都要改。
2. 跳过按钮沿用现有 `'» ' + t('intro_skip')`（`»` 安全，已在用）。
3. 省略号用 `……`（U+2026 ×2），不用 `...`。现有 i18n 已是 `我……是谁？` ✅
4. 引号推荐 `「」`；`→` 安全可用作箭头。
5. **新增任何图标符号前，先验字形**：
   > ⚠️ `ui_v4.py:92` 注释引用的 `demo/_check_glyphs.py` **当前不存在**（已核实 `demo/*.py` 文件列表）。工程需补一个，或临时用 `PIL.ImageFont.truetype('msyh.ttc').getbbox(ch)` 核验 —— 返回 `(0, 8, 17, 26)` 即为 notdef。
   > `ui_v4.py:114-117` 已有 `_GLYPH_NOTDEF` 兜底校验（命中即 `raise`），新符号表沿用同款守卫。
