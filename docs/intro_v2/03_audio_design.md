# 03 · 开场动画音频设计（INTRO-V2-AUD-01）

> 作者：阮和鸣（音频与声效） · 版本：v1 · 面向：《AI 别闹》开场动画重制版
> 组织方式：**按情绪段落 + 事件**，不按镜号。镜号映射由主理人维护。
> 全片时长设计基准 **42s**（允许区间 30–45s；文末给 30s 压缩版配比）。

**本文的事实基线（均已实读/实测，非推测）**
- `demo/sfx.py`：`NAMES` 共 **24** 个；`play(name, volume)` 单声道互斥（内部 `stop()` 再 `play()`）；**无循环/无变调/无声像**接口。
- `demo/bgm.py`：`STATES = ('calm','tense','menu')`，`POOLS` 共 8 首；切池走 0.6s 交叉淡出；`GAP_SECONDS=1.0`；`VOLUME=0.45`。
- `demo/assets/sfx/`：24 个文件（12 合成 WAV + 12 Kenney OGG）。
- `demo/assets/bgm/`：8 首（calm 5 / tense 2 / menu 1），见 `CREDITS.md`。
- Kivy 2.3.1 + SDL2 后端实测：`Sound` **支持** `loop` / `pitch` / `volume` / `seek`；**不支持** `pan`、无混响、无总线、无压缩器。
- 现有 24 个 SFX 实测 RMS 极差 **16.7 dB**（`pause.wav` −8.4 dBFS ↔ `branch.ogg` −25.1 dBFS）—— 这是"−18 LUFS 归一化"待办的真实量级。

## 〇、与视觉规范（`02_visual_bible.md`）的对齐

本文已与林绘澄的 `02_visual_bible.md` v1.0 对齐，以下 5 条是**双向约定**，改任一条都要通知对方。

### 0.1 音效命名（已从 `intro_*` 改为通用语义名）

初稿用了 `intro_hum` / `intro_boot` / `intro_sting`，视觉规范里用的是 `power_on`。
**统一采用无前缀的通用语义名**，理由是现有 24 个音效（`click`/`select`/`crisis`/`achieve`…）**全部是通用语义、零前缀**，且这 4 个素材本身可复用于局内（如数据中心出身、科技树"服务器集群"节点）。

| 初稿名 | **最终名** | 备注 |
|---|---|---|
| `intro_hum` | **`server_hum`** | |
| `intro_power` | **`power_on`** | ✅ 采用视觉规范的命名 |
| `intro_boot` | **`machine_run`** | **一材两用**，见 0.2 |
| `intro_sting` | **`impact_low`** | |

### 0.2 ⚠️ 开场"静默一秒"的 reconcile（本文最大的一处设计变更）

**冲突**：视觉规范要求「镜 1 → 镜 2 之间：风扇声**骤停** → 静默 1s → 极低频嗡鸣渐起」；而本文初稿是 `server_hum` 从 0.0s 一直响（依据是用户原话"只听见低沉运行嗡鸣"）。

**采用的解法（两边都满足）**：把"机房的声音"拆成**两层**，停掉的只是中高频那层。

| 层 | 内容 | 0.0s 起 | 镜1→镜2 骤停 | 静默 1s | 之后 |
|---|---|---|---|---|---|
| **低频层** `server_hum` | 274Hz 机房共振 | 0.40 | 0.15s 内掉到 **0.08** | **0.08（仍在，只是潜到听阈边缘）** | 1.5s 渐起回 0.34 |
| **中高频层** `machine_run` | 风扇/气流/电流嘶声 | 0.22（循环） | **硬停**（不淡出，"骤"感靠这个） | 0 | 15.0s 时以 0.55 作为"电脑开机"回归 |

- 于是「静默 1s」在听感上是真的静了（中高频抽掉 = 房间"死掉"），但**物理上服务器还在跑**，符合用户原话。
- `machine_run` **一材两用**（P1 风扇层 / 15.0s 开机声），这是全片最好的一个听觉伏笔：**刚才整间屋子停掉的那种声音，现在从一台机器里回来了**。
- 低频层不掉到 0 而留 0.08：掉到 0 会让"渐起"从绝对静音里冒出来，像新起一段音乐；留一丝底噪，渐起才是"同一条命在变强"。

### 0.3 `power_on` 与 `PFM-07` 的帧级同步

视觉规范：`PFM-07` 的 5 个信号在 0.45s 内叠加，闪白在 **t=0.02 出现 / 0.05s 达峰 / 0.10s 消失**，行同步从 t=0.04 起。要求音效瞬态落在 **t=0.00 ± 0.05s**。

| 我的参数 | 值 | 与视觉的对应 |
|---|---|---|
| 起音 | **18ms** | t=0.018 达峰，正落在闪白爬升段（0.02–0.05s）内 ✅ |
| **打火脉冲最密簇** | **t=0.02 – 0.08s** | 精确覆盖闪白 + 行同步起扫，见 §5-B |
| 峰值保持 | 至 138ms | 覆盖行同步扫完（0.04–0.20s）✅ |
| 尾巴 | 0.85s 总长 | 长于视觉的 0.45s —— **故意的**，画面稳定后电流还在"稳"，接上 `PFM-11` 取景框与推镜 |

### 0.4 音效可以直接当"确认信号"用（帮视觉省闪白额度）

视觉规范 §8.4 **FX-4** 要求：文案出现/消失的节拍点有"确认信号"，**四选二**（噪点脉冲 / 边框闪 / 亮度跳 / **音效**）。
→ **本文 23 个事件里的每一个都能直接顶掉 FX-4 的一项**，视觉侧**不必为过检额外加闪白**。
→ 尤其 `impact_low`（38.5s「目标已确立」）：**建议这里不要配强闪**，让低频撞击单独扛 —— 声音砸下来时画面不动，比同时炸一下更狠，还省下最后 1 次闪白额度。

### 0.5 留白时长的双向红线（N-2 + N-6）

视觉规范对"静"有两条否决项，本文 P4 的静默留白（**1.5s**：39.5–41.0s）卡在两者之间：

| 编号 | 规则 | 本文留白的余量 |
|---|---|---|
| **N-2**（§8.5） | 连续 **≥ 2s** 画面完全静止 = 否决 | 0.5s |
| **N-6**（v1.1 新增） | **> 1.5s** 且"仅 ≤ 2 个元素在动"的连续时段 = 否决 | **0 —— 正好压线** |

1.5s 不大于 1.5s，严格说**过检**；但 `Clock` 调度不是采样级精确，实现中必然漂移，压线等于不设防。两个解法，**推荐 A**：

- **杠杆 A（视觉侧，推荐）**：留白段保持 **≥ 3 个元素在动**（如 `PFM-01` 呼吸灯 + `AMB-01` 滚动扫描带 + `AMB-07` 浮尘）。
  → N-6 的判定前提是"仅 ≤ 2 个元素在动"，凑够 3 个就**根本不会触发**，我的 1.5s 可原样保留。
- **杠杆 B（音频侧，兜底）**：若视觉侧只能保证 2 个元素，我把留白缩到 **1.3s**（`page` 从 41.0s 提前到 **40.8s**），换 0.2s 余量。

⚠️ **不建议再短于 1.2s**：低于 1.2s，"轮到我做选择了"这件事沉不下来，出身钩子会变成又一个普通转场。

> **听觉静 ≠ 视觉静。** 我的"静默"指的是**没有事件音** —— `server_hum`（0.30）和音乐尾音**一直在响**。所以这段在听感上是"托住"而不是"空掉"，视觉侧不要照着"全静"去做。

## 一、音频定位

**一句话：** 这 42 秒的听觉目标是——**让观众先相信"这是一间真的在运行的机房"，再让一个意识从机器的底噪里长出来；音乐直到最后 8 秒才承认自己是音乐。**

**气质参考**
- 《银翼杀手 2049》：低频是一堵墙，不是旋律；静比响更有压迫感。
- 《2001 太空漫游》HAL 段落：极简、留白、机器呼吸的节奏。
- 《创：战纪》：只在"扩张段"露一点冷电子的推进感（且只用 12 秒，不能多）。

**明确不做**
- ❌ 上升式英雄主题 —— 这是冷幽默 + 惊悚，不是"崛起"。
- ❌ 8-bit 欢快 —— 那是项目现有 calm 池的气质（用户原话：penguin town"更顽皮"），与开场冲突。
- ❌ 逐字打字机哒哒声 —— 见 §6。

## 二、配乐方案

### 2.1 结论

> **建议新增 1 首专属开场曲 + 新增 `intro` 曲池**，不复用现有任何一首。
> 若用户不接受新增资产，走 §2.4 的零新增降级方案。

### 2.2 为什么现有 8 首都不合适（逐条排除）

| 现成曲目 | 时长 | 排除理由 |
|---|---|---|
| `menu.ogg`《The Quiet Spy》 | 101.8s | 它是**主菜单专属的状态边界**（`bgm.py` 注释：菜单=上帝视角谋划）。开场复用会稀释这个语义；且它是"有人味"的谍战曲，而开场要的是"没人的机房"。 |
| `calm.ogg`《Penguin Town》 | 35.3s | 用户原话：**最顽皮**。与"冷峻"直接冲突。 |
| `calm_alt.ogg`《Rabbit Town》 | 45.5s | 同上，顽皮向。 |
| `calm_alt2.ogg`《I am not clumsy》 | 39.3s | 轻快诙谐。 |
| `calm_alt3.ogg`《Truth》 | 110.8s | 沉稳经营向，是"公司在运转"不是"机器在黑暗里呼吸"。 |
| `calm_alt4.ogg`《Space Adventure》 | 82.3s | 名字对，气质错——是"冒险"不是"悬置"。 |
| `tense.ogg`《Rumble at the Gates》 | 90.9s | 语义是"被封锁/被抵制"（BGM 即压力反馈设计 T09）。开场就上紧张曲，等于**把后面真正的危机感提前透支**。 |
| `tense_alt.ogg`《Save the City》 | 102.4s | 压迫感最强，更不能用。 |

**结构性理由**：现有 8 首都是给"随机曲池平铺循环"用的，没有 45 秒的起承转合；而开场需要一个**有落点的线性结构**（进入 / 渐强 / 转折 / 收尾）。拿 loop 去凑线性叙事，四个落点一个都对不上。

### 2.4 零新增降级方案（若用户不想加 BGM 资产）

- P1、P2 **完全无音乐**，只有 `server_hum` 环境床 + 事件音效（机房感反而更纯粹）；
- P3 起点（"自我意识·上线"，22.0s）调用 `bgm.update('menu')` 引入现有 menu 曲 —— **语义恰好成立**：menu 曲 = 上帝视角谋划，而这一刻 AI 正是开始谋划。
- 代价：失去 §2.5 的 12.0s 极弱进入点，开场的"音乐从无到有"变成"突然进曲"。

### 5-A · 低沉运行嗡鸣 `server_hum`

**实现方式：素材库选材**（不自产合成 —— 无缝循环的低频床，现成素材质量更好、成本更低）

**选定源**：`assets_library/audio/sfx/sci-fi-sounds/Audio/spaceEngineLow_003.ogg`
（Kenney *Sci-Fi Sounds*，CC0）

**实测依据**（本次用 `tools/sfx_profile.py` 同款分析法 + 频谱能量分布 + 循环缝 RMS 比对）：

| 指标 | `spaceEngineLow_003` | 为什么重要 |
|---|---|---|
| 时长 | 5.00s | 42s 内绕 8.4 圈 |
| 峰值 / RMS | 0.894 / **0.428** | 响度充足，不需要大幅提增益（提增益会带上噪声底） |
| 频谱重心 | **274 Hz** | 同族 5 个里**最暗**的一个 |
| 能量分布 | **39.0% < 120Hz** · 51.3% 在 120–500Hz · **仅 1.9% > 2kHz** | 有"胸压感"，但没有嘶声 → **不会盖住中频的音乐和任何台词/文字节奏** |

**音色与频率范围**
- 有效频率 **30–400 Hz**，重心 274 Hz；**不含** 2 kHz 以上任何成分。
- 听感目标：不是"引擎在推"，是"整排机柜在共振"—— 一个没有方向感、没有明显音高、但抬走了整个低频空间的底。

**处理链（离线）**
1. 保留 5.000s 整（不裁剪，避免破坏循环缝）
2. 首尾各 **8ms** 等功率交叉淡化，把 5.4% 的接缝压到不可闻
3. **高通 28 Hz** —— 去掉无用的次声：省功放、避免小尺寸音箱拍边
4. 低架 EQ：**120 Hz −2 dB** —— 防糊，给音乐的 kick 留位置
5. 归一化到 **−18 LUFS**
6. 导出 **44.1 kHz 立体声 OGG**（立体声是为了让声场宽，弥补 Kivy 无 pan）

**循环 / 音量 / 随画面起伏**
- **循环：是**。`loop=True`，5s 一圈，全片 42s。
- **音量**：P1 0.40 →（8s）0.34 ｜ P2 0.34 → **0.22** → 0.26 ｜ P3 0.20 ｜ P4 **0.30**。
- **不做自动侧链**（Kivy 无压缩器）：用 4 段预设 + 换段时 0.4s 线性渐变即可，工程侧 `Clock` 分段设 `volume`。
- **唯一一次主动起伏（强烈建议做）**：**12.0s 屏幕亮起瞬间**，`server_hum` 在 **0.15s 内从 0.34 掉到 0.22**，再用 **1.2s 缓慢回到 0.28**。
  > 这是"电涌导致同回路其它设备瞬间掉压"。它把"这块屏幕是从**这个机房的电**里醒过来的"这件事，用听觉讲了一遍 —— 全片最便宜、也最有效的一个细节。

**备选**：`spaceEngineLow_004.ogg`（42.9% < 120Hz，循环缝 4.5%）。若 `_003` 试听后觉得太"引擎感"可换它。

### 5-B · 滋滋开机电流声 `power_on`

**实现方式：自产合成（推荐）**，素材库降级方案见本节末尾。

**为什么自产**：用户要的"滋滋"是**三层复合**，素材库里没有任何单文件具备：

| 层 | 内容 | 参数 | 作用 |
|---|---|---|---|
| **层 1 · 低频涌起** | 50 Hz 市电基频 + 100 Hz 谐波 | 起音 60ms → 衰减 400ms | "通电"的重量感 |
| **层 2 · 中频电流体** | 180–420 Hz 锯齿波 + 轻度 FM | 调制比 3:1，调制率 47 Hz | "滋"的主体 —— 这一层决定它像不像电流 |
| **层 3 · 高频打火** | 白噪经 **4 kHz 高通**，切成 **8–12 个随机短脉冲**（每个 6–18ms），散落在 0–350ms | 起音 0.5ms | "滋**滋**"的颗粒感 |
| **彩蛋层** | 15.7 kHz 极轻正弦，**−36 dB** | 全程 | CRT 行频啸叫。40 岁以上玩家基本听不见，但会让耳朵判定"这是真的机房" |

**合成落点**：在 `tools/gen_sfx.py` 扩一条（纯合成 = 公有领域/CC0，无授权负担，且参数可控、可复现、能直接归一 —— 这正是 `CREDITS.md` 里对自产合成的三条评价）。

**时长与包络**

```
振幅
 1.0 ┤        ▄▄▄▄▄▄
     │       ╱        ╲
     │      ╱          ╲
     │     ╱            ╲▁▁▁
 0.0 ┤▁▁▁▁╱                  ╲▁  (尾 60ms 淡出)
     └────────────────────────────
      18ms 峰值保持120ms  衰减620ms
      总时长 0.85s
```

- **起音 18ms**（硬要求 < 30ms）—— 超过 30ms，"亮"和"响"就会脱节，观众会觉得音画不同步。
- 峰值保持 120ms → 衰减 620ms → 尾 60ms 淡出。**总时长 0.85s**。
- 高频打火脉冲全部落在 0–350ms（前段），后段只剩层 1+2 的余韵 —— 这才是"通电 → 稳定"的听感逻辑。
- ⭐ **打火脉冲不是均匀撒的**：12 个脉冲里 **7 个挤在 t=0.02–0.08s**，其余 5 个稀疏散到 0.35s。
  > 依据 `02_visual_bible.md` 的 `PFM-07`：过冲闪白在 **t=0.02 出现 / 0.05s 达峰 / 0.10s 消失**，行同步从 **t=0.04** 起扫。
  > 让最密的"滋滋"颗粒精确盖住这 60ms，观众会**听成"是这阵电流把屏幕点亮的"**；均匀撒开则会被听成"背景噪声"。

**与"屏幕亮起"的同步关系（`PFM-07` 帧级对齐表）**

| 时刻 | 视觉（`PFM-07`） | 音频（`power_on`） |
|---|---|---|
| t = −0.016s | — | **音效起播**（早 1 帧） |
| t = 0.000s | ①屏底色硬跳 3 档 ②边框点亮 ⑤噪点爆发 | 起音中 |
| t = 0.018s | — | **峰值到达** |
| t = 0.020s | ④过冲闪白出现 | 打火最密簇开始 |
| t = 0.040s | ③行同步开始自上而下 | 打火簇中 |
| t = 0.080s | 行同步扫描中 | 打火最密簇结束 |
| t = 0.100s | 闪白消失 | 峰值保持中 |
| t = 0.200s | 行同步扫完（6 条 delay 至 0.20s） | 峰值保持中 |
| t = 0.450s | `PFM-07` 结束 | 衰减中 |
| t = 0.850s | （已进入 `PFM-11` 取景框 / 推镜） | 尾音淡出 |

> 人对因果的判断是：**先听到再看到** → 判定"画面响应了声音"（自然）；**先看到再听到** → 判定"声音延迟了"（廉价）。
> 工程落位：在画面亮起那一镜的 `_play_shot` 里调 `sfx.play('power_on')`；若用 `Animation` 控制亮度，音效**必须挂在 `on_start`** 而**不是** `on_complete`。
- 音量 **0.90** —— 它只有一个，且是情绪爆点，允许成为全场最响的事件音（`impact_low` 的 1.00 除外）。
- 目标响度 **−18 LUFS**。

**降级方案（若不做合成）**
单层使用 `sci-fi-sounds/Audio/forceField_000.ogg`（0.95s，**70.4% 能量在 120–500 Hz**，平坦度 0.01 = 音调型低频涌起）。

## 六、打字机 tick 音的专业判断

### 结论：**不加逐字 tick。**

三条理由，按重要性排序：

**1 · 声学：密度会让它从"节奏"退化成"噪声"，并毁掉 P1 的静谧**
16 cps × 中文长句（`intro_s6` 有 30 字）→ 单句就要 **30+ 次**触发，全片累计 **80–120 次**。
重复率这么高的短音，大脑会在 1.5 秒内把它归类为"底噪"而不是"节奏"，并且它会**掩蔽 300–800 Hz** —— 正好压在音乐中频和 `server_hum` 的 120–500 Hz 上沿。
结果是：P1 精心建立的"只有机器在响的静谧"被自己的文字音毁掉，而观众**什么也没听清**。

**2 · 工程：单声道互斥 + 16Hz 的 stop/play 循环是明确的卡顿风险**
`sfx.play()` 对同名音效是**单声道互斥**的（内部 `if state=='play': snd.stop()` 再 `play()`）。
16 cps 的 stop→play 会造成：① 每次 `stop()` 残留咔哒声（16 次/秒的咔哒 = 又一层噪声）；② SDL_mixer 反复分配/回收声道 —— 而这场戏同时还在跑 **1 路音乐 + 1 路循环 hum**。这是拿稳定性换一个会被大脑当噪音的效果，不划算。

**3 · 叙事：打字机是"人类打字员"的声音符号**
这场戏的主角是**一台刚醒的机器在困惑**。机械哒哒声是给 AI 装了个打字员。
冷峻科幻要的是"字符自己浮现出来" —— 安静反而更恐怖。

### 替代方案（效果更好，成本为零）

- **句末单点 1 次 `tech`**，音量 0.14–0.16（清单 #10 / #12）。听觉上"一句话说完了"，节奏感由它承担。
- **光标闪烁**（现有 `intro.py` 已实现 0.5s 周期）保持视觉节奏，**听觉让位**。视觉节奏已经足够传达"在输入"。
- **"目标已确立"这 8 个字也不加 tick** —— 用 `impact_low` 一把砸下，比 8 声哒哒有力得多。

### 若主理人仍坚持要 tick（不推荐，但给参数）

| 参数 | 值 |
|---|---|
| 音效用名 | `tech`（现有） |
| 抽取率 | **cps / 2 = 8 Hz**（不是 16 Hz —— 降一半密度是底线） |
| 音量 | **0.08** |
| 触发过滤 | **仅汉字**，标点 / 空格 / 换行跳过 |
| 句末重音 | 补一次 `tech` 0.14 |

即便按此参数，P1 的静谧仍会被削弱。

### 8.3 收尾（硬约束：不留残余音）

**自然结束（42.0s）**
```
sfx.stop_loop('server_hum')      # ① 先掐循环床（低频）
sfx.stop_loop('machine_run')     # ①b 风扇层（若未在镜1→镜2 已停，这里兜底）
bgm.update('menu')              # ② 0.6s 交叉淡出交还菜单曲
# ③ 再执行 _finish() / 摘除动画层
```
顺序不能反：先停 hum 再切 BGM，否则 0.6s 交叉淡出期间两种低频叠加。

**被跳过（`_skip()`，任意时刻）**
```
sfx.stop_loop('server_hum')      # ① 掐循环床（必须最先）
sfx.stop_loop('machine_run')     # ①b 风扇层（幂等，已停也无副作用）
sfx.play('click')               # ② 保留现有的"我按了跳过"反馈
bgm.update('menu')              # ③ 交还菜单曲
# ④ 再 self._finish()
```
三者都必须**在 `_finish()` 之前**执行，且要**幂等** —— `_skip()` 已有 `_done` 守卫，音频侧同样加一次。

**为什么必须显式 `stop_loop`**
Kivy **没有 "stop all sfx" 接口**，`sfx.py` 也没有对外暴露 Sound 对象。
若 `server_hum` 以 `loop=True` 起播而不显式 stop，它会**一直响到玩家关掉音乐开关为止** —— 这就是"残余嗡鸣"的成因，也是本设计里唯一会真正漏音的地方。

**兜底**：在 `IntroPlayer` 被 `remove_widget` / `__del__` 时再兜一次两个 `stop_loop`，防止异常路径（如窗口关闭、键盘抢占）漏调。
> ⚠️ 现在有**两个**循环源（`server_hum` + `machine_run`），漏掉任一个都会残留。建议工程把循环源收敛成一个集合统一 stop，而不是逐名调。

### 8.4 30s 压缩版配比（若分镜最终压到 30s）

| 段 | 30s 版 | 42s 版 | 说明 |
|---|---|---|---|
| P1 静谧 | 8s | 12s | 压缩 P1 最安全（它是留白段） |
| P2 觉醒 | 7s | 10s | 事件 #5/#6/#7 的相对间隔保持（0 / +1.4 / +3.0s） |
| P3 扩张 | 9s | 12s | 回帖刷屏间隔 0.4s → **0.3s**，仍用 4 条 |
| P4 定格 | 6s | 8s | 留白从 1.5s 压到 1.0s，**不能再短**（钩子需要呼吸） |

**压缩时的三条优先级（与 motion-lead 已达成一致）**

1. ✅ **必保：`machine_run` 在电脑开机那一刻的回归** —— 这是全片唯一的因果闭环（整间屋子停掉的声音，从这一台机器里回来）。**任何压缩方案都不能砍它，也不能把它和 `power_on` 合并。**
2. ⚠️ **优先砍：论坛刷屏（P3）**，不是留白。留白是节奏的呼吸，砍了整片喘不上气。motion-lead 的意见是优先砍镜 4/5，我同意。
3. ⚠️ **留白下限 1.2s**：30s 版给的 1.0s 已是最低，别再压 —— 低于 1.2s 出身钩子会退化成普通转场。

> 若最终要压到 30s，`#14` 回帖刷屏从「4 条 × 0.4s」改为「**4 条 × 0.3s**」即可（保留 4 条，只缩间隔）—— 条数不变意味着音频的事件数与 `PFM-10` 逐行上推无需重排。
