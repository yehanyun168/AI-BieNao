## ⚠️ 实测发现的真问题（P0 级，需单独立项）

**高压持续场景 fps 崩到 13.3、p50 帧时 65ms、13/13 帧全是长帧。**

两个可复现的证据链：

1. **canvas 指令数单调增长**：893 → 1139 → 1175 → … → 2851，全程无回落。
   空闲状态下没有玩家操作，指令数仍持续爬升 = **存在每帧重建/未释放**
   （典型嫌疑：Label.texture_update 反复触发、widget 未复用）。
2. **Kivy Clock 积压告警**：stderr 出现
   `[CRITICAL] Warning, too much iteration done before the next frame`，
   并列队上百个 `Label.texture_update` 回调（PxChip / RegionTab）。
   说明单帧内要处理的回调数远超 `Clock.max_iteration`，
   帧预算被回调挤爆 → 帧时线性恶化 → 崩帧。

**结论**：这不是「性能未验证」而是「已证实存在渲染层缺陷」。评审报告里
「性能 ★★☆☆☆ 零帧率数据」的评级应修正为「**已量化，且查出泄漏**」。
修复方向（建议单开任务）：定位 texture_update 高频触发源 →
改为按需刷新（值变才刷）→ canvas 指令数应稳定在常数而非单调增长。

## 备注

- perf_stress 把周期推进压缩到 2s / 1.5s 一次（真实节奏 30s/周期），
  因此 B/C 段长帧密度高于真实游玩，**只用于横向对比**，不代表真实手感。
- 本基线为**首次采集**，后续任何渲染层改动应重跑并与此表对齐。
