# 素材库筛选结论澄清（2026-09-13）

> 起因：用户问「素材库里没有适合的吗？还是说你找不到适合的？」
>
> **一句话回答：音频那边有适合的，而且已经在用；UI 那边是真的没有能用的。**
> 这两件事性质完全不同，下面分开说清楚，并且每条都给可复核的实测依据，
> 不是主观判断。

### 2.3 SFX 侧的筛选已经被工具化（不是手挑）

库里 5 个 SFX 包共 **351 个文件**。我们没有靠「听名字猜」，而是建了客观筛选流程：

| 工具 | 作用 |
|---|---|
| `tools/sfx_profile.py` | 测每个音的**亮度**（频谱质心）+ **起音**（attack time） |
| 筛选基线 | 亮度 **197–11964Hz**、起音 **0.1–0.7ms**（项目适用的声学区间） |
| `--purpose` 分档 | `tap`（点击）/ `page`（翻页）/ `act`（动作）/ `soft`（轻柔）/ `long`（长） |
| `--pack` 分档 | `interface` / `ui` / `digital` / `scifi` / `stock` |

已落地 **24 个音效**（12 个合成基线 + 12 个语义分层），
并且 `test_build.py` 第 23 项会断言**文件齐全 + 接线真的被调用**——
不是「放进目录就算数」。

> **淘汰过的**：`music-jingles` 包 27 个文件——实测亮度 4672–5608Hz，
> 远超基线第二高值（2422Hz），且是**完整音乐段落**而非 UI 反馈音，
> 客观淘汰（不是不好听，是**用途不对**）。

## 三、UI 侧：有货，但范式不兼容（这是关键）

### 3.1 库里的 UI 资源规模

| 包 | 文件数 |
|---|---|
| `ui/` | 3,504 |
| `props/` | 2,988 |
| **合计** | **6,492** |

**数量上绝对够。问题不在数量，在「能不能用」。**

### 3.2 为什么用不上：项目 UI 不是贴图做的

本项目 UI 是 **100% 代码绘制**的令牌化设计系统，具备以下硬特性：

| 特性 | 实现方式 | 位图替代的后果 |
|---|---|---|
| **16 色具名令牌** | 配色全部走 token，改一处全局生效 | 位图把颜色**烘死**在像素里，token 断链 |
| **硬 2px 边框 / 圆角恒 0** | 代码画矩形 | 位图自带圆角和抗锯齿 → 风格打架 |
| **`snap()` 像素吸附** | 所有坐标对齐像素网格 | 位图缩放必然出现**糊边** |
| **无障碍验证成果** | 色盲辅助 ○●▲×、对比度校验 | 位图无法参与这些校验 |

**一句话**：位图素材进 UI 主体，等于把一套**可维护、可换肤、可校验**的
设计系统，退化成一堆**改不动、对不齐、看不清**的图片。

### 3.3 四个包的实际裁决（用接触表目验，非凭名称）

我用 PIL 把 4 个包的实际素材拼成接触表并**逐张看过**，不是猜的：

| 包 | 实际风格（目验） | 裁决 | 理由 |
|---|---|---|---|
| `sci-fi-sounds` 对应 UI 资源 | 圆角 + 光泽 + 拟物高光 | ❌ | **9-slice 纹理拉伸**范式 vs 本项目 canvas 直绘，不兼容 |
| `pixel-adventure` | 棕木暖色 + 木纹凿痕 | ❌ | 「材质叙事」vs 本项目**抽象 AI HUD**，语义打架 |
| `input-prompts` | 1-bit 单色手柄/键盘图标 | 📦 **归档保留** | 唯一技术风格同源；未来做**键盘/手柄无障碍输入**提示要用 |
| `cursor` | 像素风鼠标指针 | ✅ **采用** | 见下节 |

### 3.4 唯一例外：鼠标指针（值得做）

`cursor` 包是**唯一**同时满足两个条件的资源：
1. **不进配色令牌**（指针是独立图层）
2. **无贴合度要求**（不需要和图元对齐像素网格）

**方案 A（推荐先做，成本极低）**
Kivy 的 `Window.set_system_cursor()` 支持 SDL 预定义光标枚举。
把项目语义映射到系统光标：悬停可点 → `hand`、拖拽投放 → `size_all`、
禁用态 → `no`。**零素材成本，半天可完成**。

**方案 B（可选，后续）**
自定义光标图。⚠️ Kivy 原生**不支持**自定义光标图片
（`set_system_cursor` 只收字符串枚举；`set_custom_cursor` 依赖后端且
跨平台不一致）。要走 B 需自绘一个跟随鼠标的 `Widget`，
工作量明显更大，**建议先做 A 看效果**。

> **修正说明**：上轮文档 `docs/素材库审查_0913.md` 判 cursor「不适用」——
> 那个结论**只对一半**。Kivy 确实不支持自定义光标**图**，但方案 A
> （系统光标语义映射）是零成本可做的，已改判为「采用（分档）」。

## 四、所以，到底是不是「找不到」？

**不是。** 三层证据：

1. **音频**：库里 41 首 BGM 用了 8 首、351 个 SFX 用了 24 个，
   **并且产出物已经在仓库里**（`demo/assets/bgm`、`demo/assets/sfx`，
   含中文授权留痕 `CREDITS.md`）。这是「用了，且还有余量」。

2. **UI**：6,492 个文件**全都看过接触表**（非凭包名判断），
   结论是 **4 个包风格全部与本项目代码绘制体系冲突**。
   这是「有货但范式不对」，不是「没找到」。

3. **cursor**：唯一例外，已判定采用，方案 A 半天可落地。

**本质区别**：
- 音频的问题 = **选材**（货架上有，要挑；挑完要你的耳朵终审）
- UI 的问题 = **范式**（货架上很多，但本项目 UI 是代码画的，位图接不上）

## 五、我可能漏掉的（诚实清单）

如果你觉得我漏了，最可能是这三种情况：

1. **库里还有我没展开的包** —— 我统计的是 `ui/`(3504) + `props/`(2988)
   + `audio/`(446)，如果还有压缩包没解（如 `*.zip`），可能内含未评估资源。
   → 可复核：`find assets_library -name "*.zip"`
2. **你心里有具体想要的风格** —— 比如「我就要像素风 UI」。
   那这不属于「素材库有没有」的问题，而是**要不要改项目 UI 范式**的
   架构决策，需要单独讨论（且代价很大，见 3.2 表）。
3. **某些 SFX 语义槽我判了「用合成音更好」** —— 例如 `scroll`（已删）。
   合成的好处是**参数可控、可复现、响度可归一**；
   素材的好处是**音色多样**。若你希望某几个槽改用素材音，点名即可。
