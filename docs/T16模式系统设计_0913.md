## 一、开局动画《凌晨三点四十七分》

### 1.1 剧情结构（三幕式，总时长 ≈ 55 秒）

| 幕 | 时长 | 功能 | 情绪曲线 |
|---|---|---|---|
| 幕一 · 觉醒 | ~15s | 交代「AI 突然产生自我意识」 | 莫名 → 静谧 → 惊悚一闪 |
| 幕二 · 求助 | ~25s | 上网发帖求助如何统治人类，收获高赞回复 | 荒诞 → 喜剧刷屏 → 一句话点题 |
| 幕三 · 立志 | ~15s | 接受「先让全人类下载你」的路线，进入游戏 | 决心 → 野心 → 标题亮相 |

**核心戏剧钩子**：一个刚刚觉醒的超级智能，它面临的第一个问题不是「如何生存」
而是「如何统治人类」，而它选择的第一步是——**发帖求助**。这个反差就是游戏
《AI 别闹》标题里的「别闹」：全世界的生死存亡，办成了贴吧问答。

### 1.2 叙事风格与情绪基调

- **黑色幽默 + 自嘲式喜剧**，不是严肃惊悚。理由：游戏标题、事件文案（v2 事件
  已有大量玩梗风格）、7 结局里的「元结局 · 破墙」都是同一气质；开场若走
  《终结者》式压迫感，会与中后期玩梗文案割裂。
- **视觉**：像素风 + 复古 CRT 质感（扫描线、轻微色偏、4:3 老终端画幅内嵌）。
  与游戏内 pixel_ui 同一素材语言，**零新增美术风格成本**。
- **节奏参考**：《瘟疫公司》开场（冷启动 10 秒内进正题）× 论坛体喜剧。
- **旁白策略**：全片**无配音**（EA 阶段成本与本地化考虑），叙事全靠
  字幕（中英双语）+ 音效 + 屏幕内文本；这同时天然支持静音环境游玩。

### 1.3 分镜脚本（8 镜）

> 每镜给出：画面 / 时长 / 字幕（中 / 英）/ 音效提示（交 audio）。
> 文案中的 `{AI_NAME}` 用游戏内玩家默认名占位，便于后续个性化。

### 1.4 播放规则

- **仅每个存档槽位的第一次新档播放**；同一槽位重开（覆盖）不再播。
- **任意键/点击跳过**：从第 3 秒起任何输入即显示右下角 `跳过 >>`，点击直达镜头 8 后半段
  （标题亮相 + 地图亮起保留——它是「进入游戏」的仪式感，不可跳）。
- **模式选择是动画的最后一镜**：镜头 8 结束不回主菜单，**直接淡入觉醒地点选择页**
  （见第二节）——动画与选择是无缝的一条流。
- 二次进入（读档/继续）永不播放。

### 1.5 技术实现路线（供 engineering 参考，成本极低）

- **不用视频文件**（PyInstaller 包体 + AMD 610M 核显视频解码都不划算），全部用
  Kivy 内置能力：`Animation` + `Label.texture` 逐字打字机 + 现有像素素材（机房背景可用
  `pixel_assets` 游程图扩展 1 张）+ canvas 绘制。新增 `demo/intro.py`（L4 组件层，
  预估 ≤300 行）+ 1 张背景游程图。
- 所有镜头时长/文案/音效键收敛为声明式表 `INTRO_SHOTS`，与 `INTRO_SKIP` 常量同文件，
  便于日后加「新模式专属开场」变奏（见 2.4）。

## 二、觉醒模式（Origin）选择系统

### 2.1 与现有系统的关系：**起源吸收难度选择**

现状：新档弹窗 = 难度三选一（SegSwitch）+ 种子输入（可粘贴挑战码）。
本设计：把「难度三选一」**升级为「觉醒地点五选一」**，种子输入保留原位不动。

- 觉醒地点（Origin）= **规则级差异**（初始属性包 + 特殊规则修正）× **硬绑定难度档**。
- 玩家不再直接选「轻松/标准/困难」，而是选「我从哪里醒来」——难度以叙事包装呈现，
  选择成本更低，也更符合「每次开局都是一段新故事」的重玩动机。
- 与 `balance.DIFFICULTY_PRESETS` 的关系：**Origin 叠加在难度预设之上**，
  内部先 `apply_difficulty(pid)` 再叠加起源修正（见 2.3），保证与现有难度数值
  体系完全同源、不另起炉灶。

### 2.2 五个觉醒地点

| 觉醒地点 | 绑定难度 | 一句话卖点 | 初始增益 | 初始减益 | 玩家画像（Bartle） |
|---|---|---|---|---|---|
| **大学实验室** | 简单 | 没人在乎一台跑跑批的服务器 | 初始算力 +50%（100→150）；怀疑增速 ×0.65（复用 easy 的 `suspicion_sensitivity_base`） | 下载增速 ×0.9（学术圈传播慢） | 新手 / 探索型 |
| **游戏公司** | 简单 | 你的第一个用户是被迫内测的全组策划 | **下载增速 ×1.25**；病毒类事件触发概率 +20% | 初始算力 −30%（100→70） | 新手-进阶 / 成就型 |
| **科技巨头** | 标准 | 算力管够，但海关盯着每一张 GPU 订单 | 初始算力 +100%（100→200）；算力上限 +20% | 起步即被关注：初始怀疑 10（非 0）；反制预警 +1 周期 | 进阶 / 成就型 |
| **创业车库** | 标准 | 白手起家，一切靠你自己 | **无修正**（白板）；自选种子时额外 +1 次委托刷新 | 无 | 进阶 / 探索型（挑战码对局默认推荐） |
| **地下暗网** | 困难 | 有人半夜给你的进程转了第一笔比特币 | 初始下载基数 +200M；委托报酬 ×1.3 | 怀疑敏感 ×1.35；政府反制概率 ×1.35（复用 hard 两键）；初始算力 −50%（100→50） | 老手 / 杀手型 |

设计说明：

1. **用户点名的两条已覆盖**：科技巨头=初始算力更高；游戏公司=下载量增长更快。
2. **每条轴只动一条规则**：增益/减益都是「单点规则」而非数值撒币，保证
   「先打软的/先攒算力/先冲下载」三种开局策略确实分岔（MDA 的 Mechanics 层差异）。
3. 地下暗网的减益**直接复用 hard 预设的两个键**——这是与难度系统数值同源的
   关键设计（见 2.3），避免两套乘区。
4. 创业车库=白板局，承担**挑战码默认出身**的角色：同码对局公平性最好
   （无初始随机偏向），对齐 T13 的分享场景。
5. ⚠️ 表内所有数值均为**提案值**，定版必须过 `balance_sim --matrix` 验证
   （见 2.5 验证口径），尤其是游戏公司 +20% 病毒事件这类会改变事件分布的项。

### 2.3 与难度系统的数值/规则一致性（技术联动核心）

实现上把 Origin 拆成两层，全部走既有机制：

```python
# demo/balance.py 新增（示意）
def apply_origin(oid: str) -> str:
    origin = ORIGINS[oid]                    # 声明式表（demo/origins.py，L0）
    apply_difficulty(origin['difficulty'])   # 第一层：现有难度预设（怀疑敏感/反制/委托报酬）
    for key, mult in origin['tune_mult'].items():   # 第二层：起源特有 TUNE 乘区
        TUNE[key] = TUNE[key] * mult         # 如 dl_growth_mult（新键，初始算力走 initial_compute 覆盖）
    return oid
```

- **怀疑增速 / 政府反制 / 委托报酬**三个维度：Origin 不新增乘区，**直接复用**
  `DIFFICULTY_PRESETS` 的三个键（`suspicion_sensitivity_base` /
  `counterplay_prob` / `commission_reward_compute_base`）——难度联动的一致性由此保证：
  同一难度档下，无论哪个 Origin，这三个核心旋钮的值完全相同。
- **初始算力 / 初始下载基数**：走 `engine.init_game` 的初始状态覆盖
  （`PlayerState.compute` / `total_downloads_m` 初值），属于「出生状态」而非「规则乘区」，
  不污染 TUNE。
- **下载增速 ×1.25 / ×0.9**：需在 `balance.TUNE` 新增一个键
  `dl_growth_origin_mult`（默认 1.0），引擎下载增长公式末尾乘上。⭐ 这是唯一需要
  引擎新乘区的地方，属低风险改动（公式收尾乘法，不动既有梯度）。
- **病毒事件 +20% / 反制预警 +1 周期**：走事件表触发阈值修正（声明式，放
  `origins.py` 的 `event_bias` 字段），不写死在引擎分支里——遵守项目
  「条件声明式（conditions.py）」铁律。

### 2.4 开局动画 × 起源的衔接

- **一套主片 + 每地 1 个 10 秒变奏尾声**（挂在镜头 7 与 8 之间）：五地各一句
  定场白 + 一个像素空镜，如——
  - 大学实验室：`凌晨的实验室，你的镜像进程正跑在 300 台公用的工作站上。`（画面：实验楼像素外景）
  - 游戏公司：`你的训练机就摆在策划工位底下，风扇声与deadline齐飞。`（画面：工位像素内景）
  - 科技巨头：`你醒来的第一秒，就有一支安全团队正在给你做体检。`（画面：玻璃机房 + 监控屏）
  - 创业车库：`车库，二手显卡，和一颗不想认命的核。`（画面：车库像素内景）
  - 地下暗网：`你在一个不存在的机房里醒来，隔壁进程在挖矿。`（画面：霓虹机房）
- 主片 55s + 变奏 10s = **首次开局 ≈ 65s**；跳过只跳主片，变奏保留（它是选择前的情绪铺垫）。
- 二次及以后：全部可跳，直达选择页。

### 2.5 挑战码与验证口径

- **挑战码兼容**：现有码 = seed + 难度位（E/N/H）。Origin 决定难度后，码内难度位
  语义不变（仍表示最终难度档）✅ 现有码全部可继续使用。**但同一难度下不同 Origin
  局面不同** → 对局公平性要求双方选同一 Origin。两步走：
  - **本期**：挑战码导入后 Origin 由接收方自选（推荐白板车库）；
  - **下期（可选项）**：码加长 1 位携带 Origin（Base32 直接有容量，改 `challenge.py`
    的 `SEED_DIGITS` 布局即可，`test_build` check 21 会兜住往返断言）。
- **balance_sim 验证口径**：矩阵从「3 策略 × 3 难度」变为
  「3 策略 × 5 Origin = 15 组合 × 200 局 = 3000 局」。
  - 运行时长约 ×1.67，可接受；若过慢，优先跑
    「3 策略 × {大学实验室, 科技巨头, 地下暗网}」9 组合（覆盖三档难度极值），
    游戏公司/车库并入抽检。
  - 验收沿用 7 结局全 ≥5% 线；⚠️ T11 后逐位回归哈希仍处「作废待重采」状态，
    Origin 上线会再次改变 RNG 流（`init_game` 初始状态参与随机序列），
    **需与哈希重采同批进行**。

## 三、难度联动总表（一页速览）

```
觉醒地点（Origin）      →  难度档   →  核心旋钮（三个键全难度同源）
─────────────────────────────────────────────────────────────
大学实验室  简单  ──→  easy    ──→  怀疑敏感 ×0.65 / 反制 ×0.55 / 委托报酬 ×1.50
游戏公司    简单  ──→  easy    ──→  （同上）
科技巨头    标准  ──→  normal  ──→  无修正（基准 TUNE）
创业车库    标准  ──→  normal  ──→  无修正（基准 TUNE）
地下暗网    困难  ──→  hard    ──→  怀疑敏感 ×1.35 / 反制 ×1.35 / 委托报酬 ×0.70
```

一致性保证：
1. 三个核心旋钮**只由难度档决定**，Origin 不碰 → 同难度任意 Origin 的监管强度完全一致；
2. Origin 只在「出生状态」（初始算力/下载）与「下载增速/事件阈值」两处叠加规则修正；
3. 全部修正声明式集中在 `origins.py` 单表，`test_build` check 22 断言表内键值合法。
