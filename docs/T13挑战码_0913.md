## 二、码格式设计

```
AINB-XXXX-XXXX-X
 │    │         └── 难度位：E / N / H（轻松 / 标准 / 困难）
 │    └──────────── 校验位（1 字符）
 └───────────────── 种子（7 字符 Base32，5 bit/位 = 35 bit 空间）
```

**字母表**：`23456789ABCDEFGHJKLMNPQRSTUVWXYZ`（32 字符）
剔除了 `0 / O / 1 / I` 四个最易混淆的字符 —— 玩家截图分享、手抄时不会把 `0` 看成 `O`。

### 关键设计决策

| 决策 | 取舍理由 |
|---|---|
| **不用明文「种子数字 + 难度」** | 明文无法察觉粘贴截断/漏字。带校验位后，抄错一位立刻显示「挑战码无效」，而不是**静默开出一局错误的种子**——后者是最伤信任的失败方式（玩家以为复现了朋友的局，其实没有） |
| **35 bit 种子空间** | 文字口令经 `sha1[:8]` 哈希是 32 bit，覆盖有余；玩家手填的小整数也全覆盖。≥2³⁵ 的巨型数字拒绝编码并提示（真随机的 `seed=None` 同样拒绝——不可复现的局分享出去是无意义码） |
| **校验覆盖难度位** | 校验和 = 前 7 位种子 + 难度字符的字母表序号和 mod 32。代价很小，换来「改难度也会被检出」 |
| **解析全容错** | 大小写无关、`-`/空格任意、可省略 `AINB` 前缀、可夹在一整段文字里链出码 |
| **先剥前缀再过滤字母表** | 前缀 `AINB` 含 `I`，而 `I` 不在字母表。若先过滤字母表，前缀会被打成 `ANB`、前缀信息永久丢失。（反向不可能误伤码体：码体取自字母表，天然不含 `I`，拼不出 `AINB`） |

### 为什么写进 `challenge.py` 而不是塞进 `main.py`

编解码 + 战绩账本放独立的 **L0 模块**（零项目依赖，只用标准库）：

- 纯函数可单测（本次 21 组往返 + 逐位变异抓错都在 `test_build` check 21 里）
- 账本目录由调用方传入（真相源 = `save_manager.SAVE_DIR`），因此**不需要 import `save_manager`**（L4）
  —— 保住了 L0 定级，也不与 L4 成环（`verify_tables` 的反向依赖检查与「未纳管模块」检查均通过）

## 三、战绩对照机制

本地账本 `demo/saves/challenge_log.json`（运行时数据，已在 `.gitignore`）。

```jsonc
{
  "AINB-2222-66LB-H": {
    "seed": 4242, "difficulty": "hard",
    "plays": 2,                         // 含本局
    "best": {...}, "last": {...},
    "runs": [...]                       // 最近 5 局明细
  }
}
```

**「最佳」的判定顺序**：`结局档位(win>neutral>lose) → 全球渗透率 → 周期数（越少越好）`。

> ⚠️ 只比渗透率是错的：被关停（lose）往往因为偷得太狠而渗透很高，会把失败局误判成最佳。
> 所以结局档位必须排在渗透率之前。

其他防御：

- **原子写**（`.tmp` → `fsync` → `os.replace`），与存档同一套路，避免半截 JSON
- **损坏回空账**：账本读不出来就当没有（战绩是锦上添花，绝不因此崩游戏）
- **账本裁剪**：最多 80 个码 × 每码 5 局明细，防止文件无限膨胀
- **幂等登记**：键 = `(码, 周期数, 结局)`，重复打开同一局结算不会刷战绩
- **对照必须先 compare 再 record**：`record()` 会把本局并入 `best`，顺序颠倒的话对照永远显示「打平」

## 六、踩坑记录（供复用时参考）

1. **`TextInput.text` 设了但截图抓不到**
   第一次跑出的两张新档截图字节数完全相同（都还是空框 + hint）。原因：TextInput 的文本
   texture 由 Clock 下一帧刷新，而 `Window.screenshot` 是 `glReadPixels` 读当前 framebuffer。
   解法：设置 `focus = True`（强制走完整重绘路径）+ 把截图延迟从 0.7s 加到 0.9s（留 2+ 帧）。

2. **前缀里的 `I` 会被字母表过滤器吃掉**
   见第二节「先剥前缀再过滤字母表」。

3. **`compare()` 必须收「登记前」的条目**
   第一版写在 `record()` 之后调用，导致 `best` 已含本局 → 永远显示「打平」。已在 docstring 里
   用 ⚠️ 显式标注调用契约。

4. **`Edit` 工具改到文件末尾会掉末尾换行**
   `i18n.py` 改完末尾不是 `\n`，`verify_tables` 的迭代计数比 `wc -l` 多 1 → 白名单误报。
   已补回换行。

## 七、已知限制 / 后续

1. **码不含成绩**：挑战码只携带 `seed + difficulty`，不含成绩。成绩对照靠**本地账本**——
   因此「朋友的最好成绩」不会显示在你这边（对方的最好成绩在他自己的机器上）。
   若要跨机对照，需要额外的「战绩分享文本」（复制一段含码 + 成绩的文本贴给对方）。
   本次未做，属可选增强。
2. **账本按机器独立**：多台机器各记各的，不冲突。
3. **真随机局无码**：开局未指定种子时结算弹窗不显示挑战码区块（设计如此）。
