## 4. 改进建议分层

每条格式：**现状问题 → 改进目标 → 实施步骤 → 工作量 → 潜在风险 → 回滚方案**

### 4.1 P0 — 阻塞上线 / 必须立即修复（≈8.5 人时）

#### P0-1　分享包与源码脱节（重建 + 加源码指纹）
- **现状**：`share/AI_Bienao_v2_20260911_1954.zip` 建于 19:54，早于 `435c51e`（21:43 大修+重平衡）与 `9246ee1`（23:46 分层修复）。解包比对确认缺失 4 项关键改动。发出去等于测旧版，M1 反馈全部作废。
- **目标**：包内容与 HEAD 严格一致，且**任何人一眼能判断是否过期**。
- **步骤**：① `tools/repack.py` 写入 `VERSION.txt`（HEAD commit hash + 打包时间戳 + 文件数 + 关键模块清单）；② 打包后完整性自检（关键模块缺失或 `demo/*.py` 未全覆盖即 `sys.exit(1)`）；③ 重打 zip；④ **在空目录解包，从包内实跑** `verify_tables.py` / `test_build.py` / `test_v4_app.py` 验证自包含。
- **工作量**：2 人时
- **风险**：包内路径含中文导致解压失败（已纳入兼容性用例）；自检过严误拦合法打包。
- **回滚**：保留旧 zip 不动，新包另命名；自检失败即中止打包，不产出。

#### P0-2　存档读取全链路容错（2 条实测崩溃）
- **现状**：`save_manager.py:96-97` 的 `json.load(f)` 无异常捕获；`:105` 直接取 `data['player']`。实测乱码存档抛 `JSONDecodeError`、缺 `player` 键抛 `KeyError`；`:98-99` 版本不符静默返回 False，玩家完全无提示。
- **目标**：任何坏档都不崩、都有明确提示，且落日志可追溯。
- **步骤**：① `load()` 包 `try/except (JSONDecodeError, KeyError, OSError, ValueError)` → 返回 False + 写 `demo/crash.log`（含原因分类）；② 版本不符返回**带原因的枚举**而非裸 False；③ UI 弹"存档损坏 / 版本过旧，将开新档"；④ 补 3 条坏档用例（乱码 / 缺键 / 版本 999）。
- **工作量**：2 人时
- **风险**：容错过宽会掩盖真实数据损坏 → 故必须落日志而非静默吞掉。
- **回滚**：`git revert` 单文件，不影响其他模块。

#### P0-3　崩溃钩子（excepthook + crash.log）
- **现状**：全库无 `sys.excepthook`（grep 仅命中测试文件），另有 37 处 `except: pass`。玩家崩溃后零留痕，M1 唯一产出（反馈）直接失效。
- **目标**：任何未捕获异常都留痕，玩家可一键回传。
- **步骤**：`main.py` 顶部装 `sys.excepthook`，写 `demo/crash.log`（traceback + Python/Kivy 版本 + HEAD hash + 简要设备信息），弹"已记录，可反馈"modal。**excepthook 内部再包一层 try 防递归异常**。
- **工作量**：1 人时
- **风险**：日志含路径/用户名等隐私 → 只写 traceback 与版本，不写个人信息（见 Q9）。
- **回滚**：删除钩子即可，无副作用。

#### P0-4　pre-commit 守卫（补今晚事故）
- **现状**：无钩子、无 CI。今晚一次"清理未使用 import"的重构引入了分层违规（L5 → L7），靠人工复跑 `verify_tables` 才发现。
- **目标**：分层违规在 commit 前被拦截。
- **步骤**：写 `.git/hooks/pre-commit`，跑 `verify_tables.py`（约 1s）+ `verify_tech_tree.py`（约 3s），非 0 退出即拒提交；设 `KIVY_NO_FILELOG=1`。同步产出 `.pre-commit-config.yaml` 供后续迁移到 CI。
- **工作量**：1 人时
- **风险**：误拦紧急提交 → 保留 `git commit --no-verify` 通道（需在 CONTRIBUTING 中写明使用守则）。
- **回滚**：`rm .git/hooks/pre-commit`。

#### P0-5　委托芯片条宽度封顶
- **现状**：`ui_commissions.py:128-136` 的 `_measure` 为 Σchip 宽，**无窗口宽度上限**；`row` 为 `size_hint=(None,None)` 的 BoxLayout，不换行不裁剪 → 5~6 单时右端飞出屏幕。且 `Clock.schedule_once(self._measure, 0)` 晚一帧，首帧宽度 40 会闪。
- **目标**：任何委托数量下都不出屏、不闪。
- **步骤**：`_measure` 改 `min(w, Window.width - 32)`，超宽时折叠为"+N"；首帧给合理默认宽度消除闪烁。
- **工作量**：2 人时
- **风险**：短文案可能被 shorten → 保留 hover/点击弹详情（已有）。
- **回滚**：还原 `_measure` 单函数。

#### P0-6　PyInstaller 补 assets（顺手修）
- **现状**：`AI别闹.spec:22-31` 的 datas 只含 8 个 .py + events.json，**无 assets/sfx**；`sfx.py:50` 文件缺失静默置 None → exe 形态下音效全哑（不崩，静默失效）。
- **目标**：exe 形态 8 个音效全响。
- **步骤**：datas 补 `('demo/assets/sfx', 'assets/sfx')`；`tools/build_exe.py` 实跑一次并校验 `_MEIPASS/assets/sfx` 内容。
- **工作量**：0.5 人时
- **风险**：路径分隔符（统一用 `/`）。**注：若 Q7 选 zip 形态，本项不阻塞 M1**。
- **回滚**：删除 datas 行。

### 4.2 P1 — 高收益重要优化（≈17.5 人时，M1 反馈后一轮做完）

#### P1-1　前段压力倒挂改造（原待办 P0-2）
- **现状**：30 局实测——首事件 1.5 周期、首委托 8.0，但**首阻止 37.8（约 18.9 分钟）、首危机 43.2（约 21.6 分钟），12/30 局 60 周期内完全无危机**。压力全压在后 5 分钟，前 20 周期零张力。（注：审查文档"前 10 分钟无事件"的说法不准确，真实问题是**压力分布**而非事件密度。）
- **目标**：首危机周期均值 ≤30（现 43.2）；60 周期无危机局 ≤3/30（现 12）。

## 6. Bug 查验清单与回归验证

> **核心原则：每一轮改动后用同一套清单判"是否引入新问题"。基线数据必须留档，任何偏离都要能解释。**

### 6.1 三级回归口径

| 级别 | 何时跑 | 内容 | 实测耗时 | 通过阈值 | 阻断规则 |
|---|---|---|---|---|---|
| **L1 快检** | 每次保存 / commit 前 | `verify_tables.py` + `verify_tech_tree.py` + `test_build.py` + `test_v4_app.py` | **11s** | 35/35、29/29、无 assert 失败、59/59，退出码均 0 | 任一 FAIL **即阻断**（pre-commit 强制） |
| **L2 标准** | 每次功能改动 / 下班前 | L1 + `balance_sim.py --seeds 30` | **≤5 min** | 7 结局全在场；平均局长 30–55；激进打法关停率 > 干净打法（现 94% vs 24%） | 出现 timeout / 结局缺失 / 局长越界 → 阻断；数值偏移仅告警但**必须贴进 commit message** |
| **L3 全量** | 发布前（人工触发） | L2 + `--seeds 100` + `check_map_palette.py`(4/4) + `verify_v4_shots.py`（**须先刷新基线**）+ 分享包自包含实跑 + 手工冒烟全表 | ≈20 min | 零 P0/P1 未关闭；冒烟 100% PASS | 存在任何未关闭 P0/P1 → 不放行 |

**"如何确认本轮未引入新问题"的判定口径（三条，缺一不可）**
1. **同基线对比**：本轮跑出的 L1/L2 结果与本轮开始前的留档逐位比对，任何差异必须能追溯到具体改动。
2. **包内实跑**：R1 起每次打包都在**空目录解包后从包内**跑 L1——本地能跑 ≠ 包内能跑（历史上已因此出过"同伴解压即崩"）。
3. **指纹比对**：`VERSION.txt` 的 HEAD hash 与仓库一致；若不一致，包视为过期，反馈作废。
