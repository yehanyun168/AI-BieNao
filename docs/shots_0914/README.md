## 4. 缺陷清单（含根因与证据）

### P0-1｜`_bind_draw` 把面板/卡片/窗口的几何全部丢掉了（4 镜受害）★ 根因已定位

`demo/intro.py:465-475`：

```python
def _bind_draw(self, wid, fn):
    def _draw(*_a):
        wid.canvas.before.clear()
        try:
            fn()               # ← ✗ 在 `with` 之外调用，指令不会进 wid.canvas.before
        except Exception:
            pass
```

`fn()`（`_draw_win` / `_draw_card` / `_draw_pan`）内部直接 `Color(...)` / `Rectangle(...)`，
**没有 `with wid.canvas.before:` 上下文**，Kivy 不会把这些指令加进该 widget 的 canvas。

**最小复现（20 行，已跑）**：

```
A) 复刻 _bind_draw 写法 → wid.canvas.before.children == []          ← 空！什么都没画
B) 正确写法 with wid.canvas.before: → ['Color','BindTexture','Rectangle']
```

**受害镜头**：SHOT05 编辑器窗口、SHOT07 帖子卡片 + 站名条、SHOT08 金卡边框、SHOT09 任务管理器面板
（含 CPU 槽/填充、高亮行底）。截图取证：S05 全图无任何边框像素；S09 面板区域（x10-54%, y25-60%）无边框像素。

**影响**：这正是项目自己的硬约束「**严禁纯字幕卡**」的验收项 **ACT-1（文案必须有载体）** ——
四镜的「载体」现在等于 0，据此**四镜均判不合格**。

**修法（约 1 行）**：把 `fn()` 包进上下文即可，例如
`with wid.canvas.before: fn()`，或在 `_draw_win/_draw_card/_draw_pan` 内部自行 `with pan.canvas.before:`。

### P0-2｜SHOT04 桌面图标渲染在屏幕原点（左下角）

`_shot_desktop`（`intro_shots.py:258-268`）里图标 body 用的是**局部坐标**：

```python
with ic.canvas:
    Color(*COLORS[cname])
    Rectangle(pos=(4, 20), size=(40, 40))   # ← 局部偏移；Kivy canvas 不自动叠加 widget.pos
```

**取证**：结构 dump 显示 5 个图标 Widget `pos=(173,290/475/660/845/1030) size=(48,64) opacity=1.0`
（属性全对），但像素扫描在该 5 处取到的都是**纯底色**；同时窗口坐标 `(4,1250)-(43,1299)` 出现一个
40×40 粉色方块 —— 即 5 个图标**全部叠印在原点**，只有最上层的粉色可见。
子标签（`pos=(-16,0)`）同理，全叠在左下角成不可读文字。

**修法（约 3 行）**：改用绝对坐标 + 位移时重绘（照抄项目既有写法）：
`Rectangle(pos=(ic.x + 4, ic.y + 20), size=(40, 40))`，并把子标签改为绝对 `pos`。

### P0-3｜SHOT03 时间码没落在画面中心

`_shot_clock`（`intro_shots.py:196-209`）把 `03`/`:`/`37` 三个 Label 放进嵌套
`FloatLayout box`，用 `pos=(0,15)/(90,15)/(120,15)` 这类**容器内相对坐标**。
真机上它们落在屏幕左下角（`03` 在 x%0-4、`37` 在 x%5-8，y%≈96→100），
不是画面中心；且亮度极低（与屏内青色底几乎同值），`03:37` 特写读不出来。
**修法（约 5 行）**：去掉嵌套容器，3 个 Label 直接用 `self._lbl(...)` 绝对定位到画面中心。

### P1-1｜结构色对比度全线不达标（机房「只剩线框」的直接原因）

以 `COLORS` 令牌实算（底色 = `dim('bg',0.8)` = RGB(10,13,18)）：

| 元素 | 取值 | 对底色对比度 | 判定 |
|---|---|---|---|
| 最近机柜填充 | `dim('panel',0.45)` | (9,12,15) → **1.01:1** | ✗ 比底色还暗一点 |
| 最远机柜填充 | `dim('panel',0.869)` | (19,23,29) → 1.08:1 | ✗ |
| 机柜描边 | `border` #30363d | 1.59:1 | ✗（图形需 ≥3:1） |
| 论坛卡边 | `border_2` #484f58 | 2.35:1 | ✗ |
| 任务栏/面板底 | `panel` #161b22 | 1.12:1 | ✗ |
| 青（指示灯/文字） | `cyan` #4ec9b0 | **9.55:1** | ✓ |

→ 只有「文字/青」够亮，**所有结构面都低于 1.3:1**，所以机房看起来是空线框、论坛/任务栏/面板像没有。
**另**：假景深公式**反了** —— `dim('panel', 0.45 + 0.55*(1-s))`，`s=0.62**i`，
即**最近**机柜取 k=0.45（最暗）、**最远**取 k=0.869（最亮），与注释/故事板的「近亮远暗」相反。

### P2-1｜暗角过厚，读成「相框」

`_build_fx`：`width = min(w,h)*0.045` = **59px**，6 层、步距 39px，相互重叠 →
四周各压出约 **237px（≈18% 屏高）** 的硬边暗框。像素图上呈现为明显的同心环「相框」，
而不是「四角柔和压暗」。建议减层/收窄（如 4 层、width 取 20~28px）。

### P2-2｜SHOT05 缺故事板要求的「被压暗的桌面」背景

`_shot_whoami` 只画了 `dimw`（0.62 黑）+ 窗口 + 文字，`bg.canvas` 为空（dump：Rect=0 Line=0 Point=0）。
故事板 SHOT 05 要求「窗口外的桌面被压暗，左下角无名 `???` 图标仍亮着（它是窗口的主人）」——
现在这个「桌面景深」不存在，画面退化为黑底文字。

### P2-3｜SHOT10 光标未跟到句末

`_cursor()` 依赖 `prompt.texture_size`/`center_x`，真机上未生效（`try/except` 静默），
光标停在初值 x=0.15w，而问句居中在 0.5w。

### P3（低置信，供复核）

隔离跑时 `content.opacity` 观测到停在 **0.61**（`_play_shot` 的 `Animation(opacity=1, d=0.12)`
未走完的残留值）。不确定是否为探针调度造成，建议工程自查一次。

## 6. 注意事项（给后续复现者）

1. **`IntroPlayer` 必须在窗口 layout 稳定后创建**。若在 `App.build()` 里创建，首镜几何会按
   Widget 默认 **100×100** 烘焙，缩成左下角一个小点（本次第一轮探针即踩此坑，已复跑修正）。
   真机 `main.py` 走的是「用户点击后创建」路径，是安全的。
2. `Window.screenshot(name=...)` 的 `name` **必须带扩展名**，否则 Kivy 把整串当扩展名生成非法路径。
3. 截图落地名会自动追加 `0001` 序号，需重命名。
4. 窗口物理宽取 1440（`%4==0`），实际渲染 2160×1320（dpi 1.5）。
5. 本目录附 `_source/` 无；全部结论可由「令牌实算 + 像素扫描 + 结构 dump」三项交叉复核。
