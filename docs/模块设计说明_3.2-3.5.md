# 《AI 别闹》模块设计说明（3.2 – 3.5）

> 本文档承接架构审查（见 `docs/架构审查_模块依赖.md`）。数据来源：对 `demo/` 53 个运行时模块的 AST 静态扫描（真实导入边 + 真实公开符号），非凭印象。
> 项目：单机地源 AI 模拟游戏（Kivy 2.3.1 + Python 3.12），目标用户为喜欢「经营/策略/反乌托邦幽默」的 PC 玩家。核心玩法：以「AI 统治世界」为壳，玩家在地图上对各国投放技能、推进科技、化解危机，按周期结算渗透率与多结局。

## 3.2 设计理念描述

### 拆解主线：以「职责分层」为主，UI 层内再按「功能」二次拆分

| 维度 | 采用 | 说明 |
|------|------|------|
| 按职责分层 | ✅ 主轴 | A 入口 → B 过场 → C 屏幕 → D 设计系统 → E 引擎/持久化 → F 内容/规则 → G 基础原语/音频，依赖严格自上而下 |
| 按功能拆分 | ✅ UI 层内 | `ui_hud/ui_pages/ui_popups/ui_input/...` 每个玩法屏一个模块，互不耦合 |
| 按流程拆分 | ❌ 有意避免 | 没有把「tick 流程」切成 step1.py/step2.py——核心模拟逻辑全部内聚在 `engine` 一个模块，避免跨文件传递状态 |

**为什么这样拆：** 模拟游戏的状态高度内聚（一局 `PlayerState` + 多国 `CountryState`），把 tick 逻辑切碎会制造大量跨文件状态传递与隐式顺序依赖，debug 极难。因此「引擎」是**单一重量级模块**（~800 行上限内），而「界面」天然可按玩法屏拆分——两者拆分策略不同，但都服务于「单一职责」。

### 哪些是最核心（缺了不可玩），哪些是加分设计

**核心架构层（ spine，缺一则游戏跑不起来或不可维护 ）**
- `engine` —— 模拟核心（tick / 胜负 / 事件 / 技能结算 / 成就 / 结局）。不依赖任何 UI（已验证）。
- `balance` —— **TUNE 数值唯一来源**（难度、出身、软饱和、危机选项）。所有数值必须走这里。
- `data` —— 国家 / 技能 / 事件内容表（`Country`/`Skill`/`GameEvent`）。
- `i18n` —— 本地化（fan-in 22，全局服务）。
- 持久化三件套 `paths`/`preferences`/`save_manager` —— 存档/设置/数据目录（冻结态统一 `%APPDATA%/AI-BieNao`）。
- 渲染基座 `pixel_ui`/`pixel_assets` + 设计系统基座 `ui_v4` —— 所有界面与组件的地基。

**内容/玩法层（定义了游戏本身，但属于「内容」而非「骨架」）**
- `tech_tree`、`endings`、`commissions`、`achievements`、`conditions`、`origins`、`v2_events`、`country_events`、`world_map`、`flag_draw` —— 这些决定「玩什么」，但都声明式 / 数据驱动，从引擎解耦。

**加分设计（增强体验，可降级或后期补强）**
- `intro`/`intro_common`/`intro_shots` —— 开场 10 镜过场（体验门面，缺失不影响玩法）。
- `ui_fx`/`cursor_fx` —— 动效（脉冲/抖动/数值滚动/光标语义），纯体验层。
- `bgm` —— 动态曲池（按怀疑度切换紧张度），失败安全，关掉照玩。
- `challenge` —— 挑战码 + 战绩账本（社交/重玩性，锦上添花，文件损坏也不崩）。
- `tutorial`/`onboarding` —— 新手引导与解锁门控（引导静默期防随机事件）。

## 3.3 模块清单初稿

> 每个模块列出：**职责** / **关键类·函数**（来自真实 AST 提取）/ **本地依赖**（它 import 的运行时模块）。
> 叶子模块（无任何本地依赖）：`bgm, challenge, conditions, country_events, cursor_fx, i18n, intro_common, onboarding, origins, paths, pixel_assets, pixel_ui, sfx, tech_tree, thresholds`。

### A · 入口与编排
- **main** — App 入口、总装 `GameUI`、驱动 tick、装配所有 Mixin。`GameUI / MainMenu / RootView / AIBienaoApp`、`read_slot_rows()`、`newest_save_path()`。
  依赖：**几乎聚合全部模块**（achievements, balance, bgm, challenge, cursor_fx, engine, i18n, intro, origins, pixel_assets, pixel_ui, preferences, save_manager, sfx, tutorial, 全部 `ui_*`）。
- **tutorial** — 新手引导步骤机。`TutorialController`（`maybe_start/next/skip/finish/replay`）、`TutorialStep`。
  依赖：`engine, main, pixel_ui, save_manager, sfx, ui_modal, ui_v4`。⚠ 含 `main`（循环，见 3.4）。

### B · 过场动画
- **intro** — 开场播放器（用完即弃）。`IntroPlayer`。依赖：`bgm, i18n, intro_common, intro_shots, pixel_ui, sfx, ui_v4`。
- **intro_common** — 镜头派生色/缓动/扫描线令牌。`dim()/alpha()/mix()`、`INTRO_SHOTS`。依赖：`pixel_ui`。
- **intro_shots** — 10 镜渲染器。`IntroShotsMixin`（`_shot_*`）。依赖：`i18n, intro_common, pixel_ui, sfx, ui_v4`。

### C · 界面屏幕层（9 个玩法屏）
- **ui_v4_screens** — 屏幕聚合器（外部统一 `import ui_v4_screens as S`）。依赖：`data, flag_draw, i18n, origins, pixel_assets, pixel_ui, sfx, ui_v4 + 全部 ui_v4_* 子面板`。
- **ui_hud** — 顶部统计/HUD。依赖：`data, engine, i18n, pixel_ui, sfx, ui_shared, ui_v4, world_map`。
- **ui_pages** — 分页主界面。依赖：`achievements, balance, data, engine, i18n, preferences, save_manager, sfx, tech_tree, ui_modal, ui_shared, ui_v4, ui_v4_screens`。
- **ui_popups** — 弹窗（结局/危机/事件）。依赖：`achievements, challenge, endings, engine, i18n, save_manager, sfx, ui_modal, ui_shared, ui_v4, ui_v4_screens`。
- **ui_session** — 对局会话屏。依赖：`bgm, engine, i18n, preferences, save_manager, sfx, ui_hud, ui_shared, ui_v4, ui_v4_screens`。
- **ui_preferences** — 设置页。依赖：`bgm, i18n, preferences, sfx, ui_shared`。
- **ui_commissions** — 委托条/委托弹窗。`CommissionBar/CommissionMixin`。依赖：`balance, commissions, data, engine, i18n, ui_hud, ui_modal, ui_shared, ui_v4`。
- **ui_drop** — 投放模式（地图多选）。`DropMixin`。依赖：`data, engine, i18n, pixel_assets, sfx, ui_fx, ui_v4, ui_v4_screens`。
- **ui_input** — 输入/操作分发（含键位、缩放）。依赖：`achievements, balance, bgm, commissions, data, engine, i18n, save_manager, sfx, tech_tree, ui_commissions, ui_fx, ui_v4, ui_v4_screens`。

### D · UI 设计系统
- **ui_v4** — 设计系统基座（令牌、配色、组件基类）。依赖：`i18n, pixel_ui, sfx`。
- **ui_v4_common** — 公共组件（卡片/页签/标题）。依赖：`flag_draw, i18n, origins, pixel_assets, pixel_ui, sfx, ui_v4`。
- **ui_v4_canvas / ui_v4_cards / ui_v4_panels / ui_v4_syspages** — 画布/卡片/面板/系统页签。均依赖：`flag_draw, i18n, origins, pixel_assets, pixel_ui, sfx, ui_v4, ui_v4_common`。
- **ui_shared** — 跨屏共享 Mixin（通用文本/布局）。依赖：`balance, i18n, pixel_ui`。
- **ui_modal** — 模态弹窗基类。依赖：`pixel_ui, ui_shared, ui_v4`。
- **ui_fx** — 动效（脉冲/抖动/数值滚动/光环）。`pulse()/shake()/count_up()/beacon()/tick_pulse()`。依赖：`pixel_ui, ui_shared`。

### E · 引擎与持久化
- **engine** — 模拟核心（见 3.5）。依赖：`achievements, balance, commissions, country_events, data, endings, i18n, onboarding, origins, tech_tree, v2_events`。**不依赖任何 UI ✅**。
- **save_manager** — 存档/读档/崩溃日志。`save()/load_ex()/list_saves()/log_crash()`、`SAVE_VERSION`、`LOAD_*` 原因码、`_MIGRATIONS`。依赖：`balance, commissions, data, engine, i18n, origins, paths`。
- **preferences** — 设置读写。`load()/save()/update()/get()`、`SETTINGS_PATH`、`DEFAULTS`。依赖：`paths`。
- **paths** — 数据目录与迁移。`_user_data_dir()/migrate_legacy_data()`（叶子）。依赖：无。

### F · 内容与规则
- **balance** — TUNE 数值唯一源。`apply_difficulty()/apply_origin()/validate()/soft_cap_suspicion()`。依赖：`origins`。
- **data** — 内容表。`Country/Skill/GameEvent` 类、`_GEO_PARAMS`。依赖：`balance, world_map`。
- **tech_tree** — 科技树。`PlayerTech`、`aggregate_effects()`、`TechBranch/TechSlot.name_for/description_for()`。依赖：无（叶子）。
- **achievements** — 成就。`check_new()/validate_cond()/get()`。依赖：`conditions, tech_tree`。
- **commissions** — 委托系统。`evaluate_commission()/generate_offer()/compute_reward()`、`CommissionState`。依赖：`balance, conditions, data`。
- **endings** — 多结局。`check_ending()/validate_cond()/Ending`。依赖：`conditions`。
- **conditions** — 声明式条件引擎（叶子）。`evaluate()/describe()/validate()/collect_keys()`。
- **v2_events** — v2 事件表。依赖：`tech_tree`。
- **country_events** — 国家专属事件。依赖：无（叶子）。
- **origins** — 觉醒出身表。依赖：无（叶子）。
- **world_map** — 像素地图。`owner_at()` 等。依赖：`pixel_assets, pixel_ui`。
- **flag_draw** — 像素国旗绘制。`FlagWidget/draw_flag()/flag_rects()`。依赖：`pixel_assets, pixel_ui`。
- **challenge** — 挑战码/战绩（叶子）。`encode()/decode()/record()/compare()/summarize()/run_rank()`。
- **thresholds** — 怀疑度阈值常量（叶子）。
- **onboarding** — 解锁门控（叶子）。`try_unlock()/unlock_budget()/in_tutorial_silence()`。

### G · 基础原语与音频（全部叶子）
- **i18n** — 本地化。`t()/set_lang()/get_lang()/get_country_name()/get_continent_name()`。
- **pixel_ui** — 像素组件原语。`PixelPanel/PixelLabel`、`color()/hex_rgba()/snap()/add_pixel_border()`。
- **pixel_assets** — 精灵图/网格资源。`parse_runs()/parse_all()/owner_at()`。

## 3.4 AI 辅助完善模块设计（资深 Python 架构师审查）

> 按你给的模板，我以「资深 Python 架构师」身份对上面 3.3 的拆解做**纯审查 + 修改建议**，不写完整代码。

### 1) 依赖方向是否合理
**整体合理，方向正确（自上而下，无向上泄漏）。** 三个判断依据：
- `engine` 不 import 任何 UI —— 模拟核心与表现层解耦，引擎可独立单测（`balance_sim` 已用 30 个种子验证）。
- UI 屏只「消费」`engine`/`data` 的状态与常量，不回写模拟 —— 单向数据流成立。
- 基础原语（`i18n/pixel_ui/pixel_assets/sfx/bgm`）全部叶子，是健康底座。

**需要修正的两点：**
- ⚠️ **循环依赖 `main ↔ tutorial`**：`main` 导入 `TutorialController`，`tutorial` 又 `from main import GameUI`。实测 `tutorial` 对 `GameUI` 仅用于惰性字符串注解（`game: 'GameUI'`），无运行期引用。**建议**：删 `tutorial.py` 的 `from main import GameUI` 并加 `from __future__ import annotations`，破环后仅留 `main → tutorial` 单向（编排者依赖控制器，方向正确）。这是 P1 清理项。
- ⚠️ **UI 层直接 import `engine` 而非一个薄门面**：`ui_pages/ui_input/ui_commissions/ui_drop` 等都直接 `import engine`。当前 `engine` 是单模块，可接受；但随功能增长，建议抽出一个 `engine_api`（或约定 `engine` 只暴露公开函数、内部 `_*` 不对外），避免 UI 误用引擎私有状态。

### 2) 哪些接口可能出问题（风险接口）
- 🔴 **`i18n.t(key)` 缺少缺失校验**：`i18n` 模块**没有 `validate()`**（对比 `balance/achievements/endings/conditions` 都有）。缺失的翻译键会静默回退（空白或显示 key 本身），只在运行期某一屏偶发出现，难发现。**建议**：新增 `i18n.validate()`，在启动时遍历 `TRANSLATIONS` 校验中英键集一致，与现有 `verify_*` 自检串起来。
- 🟠 **`data` 内容表无 `validate()`**：`Country/Skill/GameEvent` 是手工数据表，`data` 也没有静态校验。字段名拼错只会在 `engine` 运行期 KeyError。**建议**：补 `data.validate()`（参照 `conditions.validate()` 的「返回问题清单」风格）。
- 🟠 **`save_manager.load_ex()` 的 `_MIGRATIONS` 迁移链**：每次改 `PlayerState` 字段都要新增迁移步骤，否则老档 `LOAD_BAD_SCHEMA`。风险不在接口签名，而在「改引擎结构必同步迁移」的纪律——建议把迁移步骤写进提交模板（已在项目约定里强调）。
- 🟢 **`sfx.play()/bgm.*` 失败安全设计良好**：关闭/未加载/异常一律 no-op 或回退，不会因音频缺失崩游戏——保持这个约定，新增音效继续沿用 `load_all()` 幂等 + 失败单条置 None 的模式。
- 🟢 **`engine` 的 `preview_*` 纯函数**：`preview_skill()/preview_next_cycle()` 不写状态，UI 实时预览依赖其返回形状，是稳定契约——建议在 3.5 把它列为「稳定接口，改返回结构须同步 UI」。

### 3) 是否遗漏了必要模块
- 🟡 **建议补一个轻量「事件/消息总线」**：当前 UI↔引擎靠 Kivy 事件和 `app` 句柄的鸭子类型耦合（弱依赖，静态图看不见）。模块一多，屏间流转和「引擎→UI 通知」会散落各处。**建议**：引入一个极简 `EventBus`（发布/订阅），让 `engine` 通过事件通知 UI（如 `on_cycle_end`、`on_ending`），降低 UI 对 `engine` 的内部耦合。非强制，但能显著减少 3.4-1 提到的「UI 直连 engine」问题。
- 🟡 **`i18n` / `data` 的校验器缺失**（见上）——属于「该有但还没的模块能力」，不是独立模块。
- ✅ **不缺运行时网络 / 物理 / 资源管理模块**：单机游戏，GitHub 仅用于分发；资源在加载期由 `pixel_assets` 载入。这三点**不是遗漏，是设计使然**，无需补齐。

## 3.5 调整后的接口文档主体

> 经 3.4 审查调整后的核心接口。约定：**逻辑校验类接口返回「问题清单 / 原因码」而非抛异常**；**资源/运行期接口失败安全（no-op 或回退）**。

### i18n（本地化 · 全局服务）
```python
t(key: str, **kwargs) -> str
```
- **参数**：`key` 翻译键；`kwargs` 用于 `{name}` 占位插值。
- **返回**：本地化字符串；缺失键**静默回退**（当前回退中文或 key 本身）。
- **异常**：无（故意 fail-safe）。
- **备注**：🔧 建议新增 `validate() -> list[str]`（空=合法），启动自检遍历 `TRANSLATIONS` 校验中英键集一致。
- 配套：`set_lang(lang)` / `get_lang()` / `get_country_name(code)` / `get_continent_name(code)`。

### engine（模拟核心 · 纯逻辑，不依赖 UI）
```python
init_game(...) -> (PlayerState, list[CountryState])      # 初始化一局
tick_one_round(state) -> list[str]                       # 推进一个完整周期，返回人类可读日志
use_skill(state, skill_id, targets) -> list[str]          # 释放技能（支持地图多选目标）
preview_skill(state, skill_id, targets) -> PreviewResult  # 纯函数预测，不写状态
preview_next_cycle(state) -> dict                         # 纯函数预测下周期确定性强度
check_ending(state) -> Ending | None                      # 按优先级判定结局
resolve_choice(state, event_id, choice_id) -> list[str]   # 结算 v2 事件选项
accept_commission(state, offer) / decline_commission(...)  # 委托接单/放弃
resolve_crisis(state, option) -> list[str]                # 结算危机三种生路
```
- **返回**：日志/数据快照/常量；逻辑无效多返回 `None` 或 `PREVIEW_*` 常量（不抛）。
- **异常**：期望调用方先做合法性校验；非法操作由 `target_availability()`（`TARGET_OK/LOCKED/NO_COMPUTE/SATURATED/BLOCKED`）前置判定。
- **备注**：引擎是单测核心（`balance_sim --seeds 30` 基线）。🔧 `preview_*` 返回结构列为稳定契约，改结构须同步 UI。

### save_manager（持久化）
```python
save(state, slot: str) -> str                 # 存档，返回实际写入路径
load_ex(slot: str) -> tuple[bool, int]        # (ok, reason)
list_saves() -> list[str]                     # 按修改时间倒序
log_crash(text: str) -> None                  # 崩溃钩子写 crash.log
```
- **reason 码**：`LOAD_OK / LOAD_MISSING / LOAD_CORRUPT / LOAD_BAD_VERSION / LOAD_BAD_SCHEMA`（供 UI 分支显示文案）。
- **异常**：IO 错误捕获后走 `load_fail_text()`（i18n 文案），不向上抛。
- **备注**：`_MIGRATIONS` 字典按 `SAVE_VERSION` 迁移老档；🔧 改 `PlayerState` 字段必须同步加迁移步骤。

### preferences（设置）
```python
load() -> dict
save(d: dict) -> None
update(key, value) -> None     # 改后立即落盘
get(key, default=None)
```
- **备注**：`SETTINGS_PATH` 来自 `paths._user_data_dir()`（冻结态 `%APPDATA%/AI-BieNao`）。

### paths（数据目录）
```python
_user_data_dir() -> str            # 冻结态 %APPDATA%/AI-BieNao；源码态 demo/
migrate_legacy_data() -> None      # 把旧 exe 同级 settings/saves/crash.log 复制到 APPDATA
```
- **备注**：冻结态**只 copy 不 move**（源保留）；逐文件 `try/except`；仅冻结态执行。

### sfx / bgm（音频 · 失败安全）
```python
sfx.play(name: str) -> None                 # 关闭/未加载/异常 → 静默 no-op
sfx.play_loop(name) / stop_loop(name) / stop_all_loops()
bgm.update(pool: str) -> None               # 切换曲池（幂等）
bgm.state_for_suspicion(suspicion: float) -> str   # 怀疑度 → 曲池（calm/tense…）
```
- **备注**：`load_all()` 幂等，失败单条置 `None` 不影响其它；`stop_all_loops()` 用于开场/退出防漏音。

### balance（数值唯一源）
```python
apply_difficulty(pid) -> str        # 还原基准后应用难度乘数，返回生效档
apply_origin(oid) -> str            # 应用觉醒出身 TUNE 乘区
validate() -> list[str]             # 空=合法，供启动自检/CI
soft_cap_suspicion(x) -> float      # T04 尖峰治理：膝点+软饱和
```
- **备注**：所有数值必须走 `balance.TUNE`，禁止在别处硬编码魔法数。
